# 模块与可见性

> [!abstract] 一句话
> 模块树是编译期的结构：`mod` 决定「代码放在哪」，`pub` 家族决定「谁能看见」，`use` 只是给长路径起短名——它既不移动代码，也不改变可见性。

## 为什么需要它

真实项目很快就不再是一个文件能装下的：类型、函数、常量会成百上千。C 用头文件加 `static` 表达「仅本文件可见」，但同一编译单元内所有符号互相可见；Java 把可见性绑在目录和 `public` 上，却写不出「只对子模块开放」；Python 的 `_` 前缀只是约定，运行时毫无约束。

Rust 把可见性做进了类型检查：模块树在编译期确定，越界访问直接编译失败，而且不带来任何运行时开销。它还把「一个模块」和「一个文件」解耦——内联 `mod` 与拆成文件，是同一棵树的两种写法（[[02-Cargo 与项目结构|Cargo 与项目结构]]）。

## 模块树与文件布局

`mod foo;` 是**声明**而不是引入：编译器据此去同目录找 `foo.rs` 或 `foo/mod.rs`，目录结构由此映射成模块树。

```text
src/main.rs        crate 根，里面写 mod engine; mod ui;
src/engine.rs      模块 crate::engine 的全部内容
src/engine/mod.rs  等价写法，与 engine.rs 二选一
src/ui.rs          模块 crate::ui
src/ui/widgets.rs  需要 ui.rs 里写 mod widgets; 才存在
```

两条规则记住就不会迷路：

- 声明与文件必须对得上：`mod foo;` 找不到文件就报 `file not found for module`；子模块文件放在父模块同名目录里（`ui.rs` 配 `ui/widgets.rs`）。
- 同一模块只能定义一次：内联 `mod foo { }` 和 `mod foo;` 同时存在会因重名而编译失败。

## 三种相对路径

| 写法 | 起点 | 例子 |
| --- | --- | --- |
| `crate::` | 当前 crate 的根 | `crate::engine::Engine` |
| `super::` | 上一层模块 | `super::helper()` |
| `self::` | 当前模块（可省略） | `self::line::name()` |

在 2018 之后，`fn` 里的路径可以写成相对当前模块的形式，但**结构体、枚举、`use` 语句默认从 crate 根或外部 crate 解析**，所以跨模块时养成写 `crate::`/`super::` 的习惯最省事。

## 可见性：pub 的四档

| 写法 | 谁能访问 |
| --- | --- |
| `pub` | 任何地方，前提是路径上每一层都够得着 |
| `pub(crate)` | 当前 crate 内任意位置，对外完全不可见 |
| `pub(super)` | 父模块及其子树 |
| `pub(in crate::a::b)` | 指定的那个祖先模块子树 |
| 不写（私有） | 当前模块**及其子模块** |

最后一条最容易被忽略：私有项对**子模块**可见，因为子模块天然是父模块的实现细节。反过来不成立——父模块不能碰子模块的私有项。

`pub` 管的是「名字能否被路径找到」，不是「值能不能用」。一个 `pub struct` 的字段默认仍是私有的，外部拿得到类型、拿不到字段（`E0616`）。

## use 与重导出

`use` 只是把路径绑定到当前模块，可以叠加 `pub` 变成**重导出**：对外暴露短路径，同时藏起内部模块结构。

```rust
mod factory {
    // 私有：只有 factory 及其子模块能调
    fn secret() -> u32 { 7 }

    // 只对当前 crate 可见，外部 crate 完全看不到
    pub(crate) fn helper() -> u32 { secret() }

    pub mod line {
        // 只对父模块 factory 可见
        pub(super) fn build() -> u32 { 1 }
        // 完全公开
        pub fn name() -> &'static str { "line-1" }
    }

    pub fn produce() -> String {
        // 子模块内的代码也能调父模块的私有函数
        format!("{}:{}:{}", line::name(), line::build(), helper())
    }
}

// 重导出：调用方不必写 factory::line::name
pub use factory::line::name;

fn main() {
    // crate:: 是绝对路径，从 crate 根出发
    assert_eq!(crate::factory::produce(), "line-1:1:7");

    // 重导出之后短名即可使用
    assert_eq!(name(), "line-1");
    println!("{}", name());
}
```

注意 `factory` 本身是私有的，但 `pub use` 依然能把里面的 `pub` 项拿出来公开——这正是「公开 API + 隐藏内部模块」的标准做法。

## 模块内测试

测试函数习惯和被测代码放在同一个文件里，用子模块 + `#[cfg(test)]` 隔离：普通构建时整块代码不参与编译，`cargo test` 时才展开。这样做的好处是能测**私有**函数。

```rust
mod calc {
    pub fn double(x: i32) -> i32 {
        x * 2
    }

    // 只在 cargo test 时编译，发布产物里没有这段
    #[cfg(test)]
    mod tests {
        use super::double; // super:: 指回 calc 模块

        #[test]
        fn doubles() {
            assert_eq!(double(21), 42);
        }
    }
}

fn main() {
    assert_eq!(calc::double(3), 6);
    println!("double(3) = {}", calc::double(3));
}
```

## 私有性编译错误

跨模块访问越界时，报错通常长这样——错误信息会直接指出「private」这一层：

```text
error[E0603]: module `engine` is private
  --> src/main.rs:3:20
   |
 3 |     let e = mylib::engine::Engine::new();
   |                    ^^^^^^ private module
```

修复只有两条路：给路径中间那层模块加 `pub`，或者在上一层用 `pub use` 把需要的东西重导出成短路径。

## 常见错误与解决

| 错误 | 原因 | 解决 |
| --- | --- | --- |
| `E0603: module ... is private` | 路径中间某一层模块没标 `pub` | 给该层加 `pub`，或改用 `pub use` 重导出 |
| `E0616: field ... is private` | 结构体字段默认私有 | 字段加 `pub`，或提供 `get`/`set` 方法 |
| `E0428: name ... is defined multiple times` | 内联 `mod foo` 与 `mod foo;` 同时存在 | 二者只留一个 |
| `file not found for module` | 缺少 `foo.rs` / `foo/mod.rs` | 建文件，或改成内联模块 |
| `unresolved import` | 相对路径写错，或是 `use` 里少了 `crate::` | 补全 `crate::`/`super::`/`self::` |

## 练习

1. 把上面的三层内联模块拆成 `main.rs` + `factory.rs` + `factory/line.rs`，写出每个文件里的 `mod` 声明。
2. 解释为什么子模块能调用父模块的私有函数，而父模块调不到子模块的私有函数。
3. 把 `helper` 从 `pub(crate)` 改成 `pub(super)`，说明 `produce` 里还能不能调用它。
