# 变量与数据类型

> [!abstract] 一句话
> `let` 绑定默认**不可变**，要改就加 `mut`；标量、元组、数组都是**定长、栈上**的类型，长度在编译期确定。

## 为什么需要它

C 的变量默认可变，`const` 只是个提示；Python 的变量是名字到对象的绑定，类型随运行时而变；Java 有静态类型但默认可变且整数溢出静默回绕。Rust 把三件事同时收紧：**默认可变性**（要写 `mut` 才能改）、**编译期类型检查**（无隐式转换）、**整数溢出检查**（debug 下直接 panic）。代价是打字多一点，收益是绝大多数「值被意外改掉」和「溢出回绕」的 bug 在编译期或首次运行时就暴露。

## 核心规则

### `let` / `mut` / 常量 / 静态变量

| 写法 | 可变性 | 作用域 | 何时求值 |
| --- | --- | --- | --- |
| `let x = 1;` | 不可变 | 块内 | 运行时 |
| `let mut x = 1;` | 可变 | 块内 | 运行时 |
| `const MAX: u32 = 100;` | 不可变 | 任意（可导出） | **编译期**，必须标注类型 |
| `static NAME: &str = "a";` | 默认不可变，`static mut` 需 `unsafe` | `'static` 全程 | 编译期，有固定内存地址 |

`const` 会被内联到每个使用处，没有地址；`static` 有唯一地址，适合需要全局单例语义的场景。惯例是**优先 `const`**，`static mut` 基本不要碰，用 [[thread|std::thread]] 相关的同步原语或 `OnceLock` 替代。

### 遮蔽（shadowing）：同名重新绑定

```rust
fn main() {
    let spaces = "   ";        // &str
    let spaces = spaces.len(); // 重新绑定成 usize，类型可以变
    println!("{}", spaces);    // 3
}
```

遮蔽不是「修改」，而是**新变量覆盖旧名字**，旧值在无人引用后被丢弃。它允许换类型，所以做「解析 → 校验」的链式转换很顺手。与之相对，`mut` 只能改值不能改类型。

### 标量类型

| 类别 | 类型 | 说明 |
| --- | --- | --- |
| 有符号整数 | `i8` `i16` `i32` `i64` `i128` `isize` | 默认 `i32`；`isize` 宽度随指针 |
| 无符号整数 | `u8` `u16` `u32` `u64` `u128` `usize` | 索引一律用 `usize` |
| 浮点 | `f32` `f64` | 默认 `f64`；不实现 `Eq`，不能直接比较相等 |
| 布尔 | `bool` | `true` / `false`，**不能**当整数用 |
| 字符 | `char` | 单个 Unicode 标量值，4 字节；字符串用双引号、`char` 用单引号 |

数字字面量可以加下划线和后缀：`1_000_000`、`0xff`、`0o77`、`b'A'`、`3.14_f64`。整数类型见 [[primitive.整数类型|整数类型]]，浮点见 [[primitive.浮点类型|浮点类型]]。

### 整数溢出与 `checked_*` 系列

默认行为按构建模式分叉：

- **debug 构建**：溢出直接 panic，报 `attempt to add with overflow`。
- **release 构建**：静默按二进制补码回绕（wrap）。

要显式控制就用 `u8` 等整数上的方法族：

| 方法 | 溢出时 |
| --- | --- |
| `checked_add(n)` | 返回 `None` |
| `wrapping_add(n)` | 回绕，返回结果 |
| `saturating_add(n)` | 封顶到 `MAX` |
| `overflowing_add(n)` | 返回 `(结果, 是否溢出)` |

完整列表（`checked_sub`、`checked_mul`、`checked_div`…）在整数类型页里有。**处理外部输入时一律用 `checked_*`**，别依赖「debug 会 panic」——线上跑的是 release。

### 元组与数组

- **元组** `(T1, T2, ...)`：长度固定，元素**类型可以不同**，用 `.0` `.1` 或模式解构访问。
- **数组** `[T; N]`：长度 `N` 是类型的一部分，元素类型相同，连续存放在栈上。

需要可增长就用 `Vec<T>`，见 [[12-集合类型|集合类型]]；数组更适合固定大小的小缓冲区。

### 类型推断与显式标注

编译器通常能从上下文推出类型，推不出时才需要标注。三处例外要显式写：`const`/`static`、函数签名（参数和返回值）、以及**解析字符串时的目标类型**——`"42".parse()` 不标注就报 `E0283`。

### 类型转换：`as` 与 `From` / `Into`

| 方式 | 特点 | 什么时候用 |
| --- | --- | --- |
| `as` | 静默截断、饱和或重解释，**不会报错** | 数字之间、`char` 与整数之间的底层转换 |
| `From` / `Into` | 无损转换，编译期保证不丢信息 | 目标类型一定能容纳源值时 |
| `TryFrom` / `TryInto` | 可能失败的转换，返回 `Result` | 可能越界或非法时 |

原则：**能 `From` 就 `From`，可能失败就 `TryFrom`，`as` 只在明确知道会截断时用**。`as` 在 `f64 → i32` 上是饱和的（`NaN` 变 0，超界变边界值），在整数之间是截断的，行为都不报错，所以最危险。

## 代码示例

第一段覆盖绑定、遮蔽与常量：

```rust
const MAX_POINTS: u32 = 100_000;

fn main() {
    let x = 5;              // 不可变
    let mut y = 10;         // 可变
    y += 1;
    // x += 1;  // ❌ 编译错误 E0384: cannot assign twice to immutable variable

    let s = "123";          // &str
    let s: u32 = s.parse().unwrap(); // 遮蔽：同名换类型，解析失败会 panic

    let z = 3.0_f64 / 2.0;
    let c = '中';
    let b = true;

    println!("x={} y={} s={}", x, y, s);
    println!("z={} c={} b={} MAX={}", z, c, b, MAX_POINTS);
}
```

第二段演示溢出处理与元组、数组：

```rust
fn main() {
    let big: u8 = 250;

    // 溢出不会 panic 的三种写法
    assert_eq!(big.checked_add(10), None);
    assert_eq!(big.wrapping_add(10), 4);
    assert_eq!(big.saturating_add(10), u8::MAX);
    assert_eq!(big.overflowing_add(10), (4, true));

    // 元组：类型可不同，用 .0/.1 或解构访问
    let pair: (i32, &str) = (7, "seven");
    let (num, name) = pair;
    println!("{} = {} / {}", pair.0, num, name);

    // 数组：长度是类型的一部分
    let mut arr: [i32; 3] = [1, 2, 3];
    arr[0] = 10;
    println!("第一个 {}，长度 {}", arr[0], arr.len());

    // 显式转换：as 截断，TryFrom 报错
    let n: i32 = 300;
    assert_eq!(n as u8, 44);
    assert!(u8::try_from(n).is_err());
    let ok: u8 = u8::try_from(200_i32).unwrap();
    let widened: i64 = i64::from(ok);
    assert_eq!(widened, 200);
}
```

## 常见错误与解决

| 错误 | 原因 | 解决 |
| --- | --- | --- |
| `E0384: cannot assign twice to immutable variable` | 对没有 `mut` 的变量赋值 | 加 `mut`，或改用遮蔽重新绑定 |
| `E0308: mismatched types` | 类型不匹配，Rust 不做隐式转换 | 用 `as`、`From`/`Into` 显式转换 |
| `E0283: type annotations needed` | `parse()` 等泛型方法推不出目标类型 | 写 `let n: u32 = s.parse()?;` |
| `attempt to add with overflow` | debug 构建下整数溢出 | 换 `checked_add` / `saturating_add`，或用更大类型 |
| `E0004: non-exhaustive patterns` | 解构元组/数组时漏了分支 | 补全模式，或用 `..` 忽略剩余 |

## 练习

1. 声明 `let x: u8 = 200;`，分别用 `checked_add`、`wrapping_add`、`saturating_add` 加 100，写出三种结果并解释。
2. 把 `let data = [0u8; 4];` 的第 2 个元素改成 `0xff`，再打印整个数组；说明为什么不能把 `Vec<u8>` 直接塞进 `[u8; 4]`。
3. 写一个把 `f64` 转成 `u32` 的函数，要求遇到负数或超出范围时返回 `Option<u32>`，不允许用 `as`。
