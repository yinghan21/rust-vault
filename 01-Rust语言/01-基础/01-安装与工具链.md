# 安装与工具链

> [!abstract] 一句话
> `rustup` 管「安装与切换」，`rustc` 管「编译单个文件」，`cargo` 管「整个项目」——日常开发你几乎只需要跟 `cargo` 打交道。

## 为什么需要它

C/C++ 要自己配编译器、链接器和构建脚本；Java 得先装 JDK 再上 Maven/Gradle；Python 的依赖管理还要另外装 `pip`、`poetry`。Rust 把这些一次性收进官方工具链：装好 `rustup` 之后，编译器、标准库、包管理器、格式化工具、lint 全部就位，不会出现「版本对不上」的经典麻烦。

Rust 还有一处别处少见的能力：**同一台机器上并存多个版本的编译器**，并且可以在目录级别锁定版本。这正好解决「老项目跑在 2015 edition、新项目想用 2021 edition」的冲突。

## 核心规则

### rustup / rustc / cargo 各管什么

| 工具 | 角色 | 典型命令 |
| --- | --- | --- |
| `rustup` | 工具链管理器：安装、更新、切换 | `rustup update`、`rustup show` |
| `rustc` | 编译器本体：编译 `.rs` 源文件 | `rustc main.rs` |
| `cargo` | 项目管理器：依赖、构建、测试、发布 | `cargo build`、`cargo test` |
| `rust-analyzer` | 语言服务器，给编辑器提供补全与跳转 | 编辑器自动调用 |
| `clippy` | 官方 lint 集合，找可疑写法 | `cargo clippy` |
| `rustfmt` | 官方格式化工具 | `cargo fmt` |

`rustup` 往 `~/.cargo/bin/` 放一组「代理程序」（shim）：你敲 `cargo` 时执行的是 `~/.cargo/bin/cargo`，它再按当前工具链去调用真正的 `cargo`。所以**不要手动把某个编译器路径塞进 `PATH` 前面**，那会绕过 rustup，工具链切换随即失灵。

### 安装

Linux / macOS 用官方脚本；Windows 下载 `rustup-init.exe`：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

Windows 上默认链接 MSVC，所以需要 Visual Studio Build Tools 里的「使用 C++ 的桌面开发」工作负载，否则会在链接阶段报 `link.exe` 找不到。

### 国内镜像配置

工具链下载源在境外，网络不稳时把两个环境变量指向国内镜像（这里以 rsproxy 为例）：

```bash
export RUSTUP_DIST_SERVER="https://rsproxy.cn"
export RUSTUP_UPDATE_ROOT="https://rsproxy.cn/rustup"
```

PowerShell 里写法不同：

```powershell
$env:RUSTUP_DIST_SERVER = "https://rsproxy.cn"
$env:RUSTUP_UPDATE_ROOT = "https://rsproxy.cn/rustup"
```

想永久生效就写进 `~/.bashrc`、`~/.zshrc` 或系统环境变量。crate 依赖的镜像则配在 `~/.cargo/config.toml` 的 `[source.crates-io]` 下，属于 cargo 的配置，见 [[02-Cargo 与项目结构|Cargo 与项目结构]]。

### 编辑器：VS Code + rust-analyzer

1. 安装官方扩展 `rust-analyzer`（发布者 rust-lang）。
2. 不要同时启用旧的 `Rust`(rls) 扩展，两者会重复提供诊断，互相打架。
3. 用 VS Code 打开**含 `Cargo.toml` 的目录**，而不是单个 `.rs` 文件，否则补全和跳转都所剩无几。

`rust-analyzer` 内部跑的就是 `cargo check`，因此**项目必须能被 cargo 正常加载**。`Cargo.toml` 一写错，补全会整体失效——这时去看「输出 → rust-analyzer」面板，错误原文就在那里。

### 项目目录结构

`cargo new hello` 之后得到：

```text
hello/
├── Cargo.toml        # 项目清单：包名、版本、依赖
├── Cargo.lock        # 锁定文件：记录实际用到的依赖版本
├── src/
│   └── main.rs       # 二进制 crate 的入口
└── target/           # 编译产物，可随时删除
```

`target/` 常有几百 MB，它只是缓存，删掉不丢代码，下次编译重建；`.gitignore` 默认已忽略它。

### 常用命令

| 命令 | 作用 |
| --- | --- |
| `cargo new 名字` | 新建二进制项目；加 `--lib` 则建库 |
| `cargo build` | 编译 debug 版，产物在 `target/debug/` |
| `cargo build --release` | 编译优化版，产物在 `target/release/` |
| `cargo run` | 编译并运行；给程序的参数写在 `--` 之后 |
| `cargo check` | 只做类型检查不生成可执行文件，比 `build` 快得多 |
| `cargo test` | 编译并运行测试 |
| `cargo fmt`、`cargo clippy` | 格式化、静态检查 |
| `cargo doc --open` | 生成并打开项目文档 |

日常节奏是：写代码 → `cargo check` 看错误 → 改完 → `cargo run`。`check` 省掉代码生成和链接，在中型项目上能快数倍。

### 工具链与版本切换

```bash
rustup show                      # 当前装了哪些工具链、正在用哪个
rustup toolchain list            # 列出全部工具链
rustup toolchain install 1.75.0  # 装一个具体版本
rustup default stable            # 改全局默认
rustup override set 1.75.0       # 只在当前目录固定版本
rustup override unset            # 取消目录级固定
rustup component add clippy      # 给当前工具链加组件
```

三条渠道：`stable`（每 6 周发一版）、`beta`、`nightly`（每天构建，能开实验特性）。业务项目留在 `stable`，只有需要实验特性或跑基准时才用 `nightly`。

更推荐的做法是在项目根目录放一个 `rust-toolchain.toml`，把版本声明成文件，团队成员和 CI 会自动切到同一版本：

```toml
[toolchain]
channel = "1.75.0"
components = ["rustfmt", "clippy"]
```

## 代码示例

不用 cargo，`rustc` 也能直接编译单个文件——这能帮你分清「编译器」和「构建系统」：

```rust
fn main() {
    println!("Hello, Rust!");
}
```

```bash
rustc --edition 2021 main.rs   # 生成 main（Windows 上是 main.exe）
```

再写一段用标准库读取当前平台信息的程序，顺便验证工具链真的就位了：

```rust
use std::env::consts;

fn main() {
    // 以下常量在编译期由目标三元组（target triple）决定
    println!("操作系统：{}", consts::OS);
    println!("处理器架构：{}", consts::ARCH);
    println!("usize 宽度：{} 字节", std::mem::size_of::<usize>());
}
```

## 常见错误与解决

| 错误 / 现象 | 原因 | 解决 |
| --- | --- | --- |
| `command not found: cargo` | `~/.cargo/bin` 不在 `PATH` 里 | 重开终端；或手动把该目录加入 `PATH` |
| `linker 'link.exe' not found` | Windows 缺 MSVC 链接器 | 装 VS Build Tools 的「使用 C++ 的桌面开发」 |
| `toolchain 'nightly-x86_64-...' is not installed` | 没装对应工具链 | `rustup toolchain install nightly` |
| `cargo` 能用但编辑器没补全 | 项目没被 cargo 成功加载 | 检查 `Cargo.toml`；看 rust-analyzer 输出面板 |
| 下载工具链超时 | 境外源不可达 | 配置 `RUSTUP_DIST_SERVER` 镜像后重试 |
| 编译报出莫名其妙的错误 | `rust-toolchain.toml` 悄悄切换了版本 | `rustup show` 确认实际版本 |

## 练习

1. 用 `rustc` 直接编译一个打印「平台 + 你的名字」的文件，再用 `cargo new` 建同样功能的项目，比较两种流程的差别。
2. `rustup override set nightly` 只在本目录切到 nightly，用 `rustup show` 确认后 `rustup override unset` 恢复，观察全局默认是否被影响。
3. 删掉 `target/` 再 `cargo run`，观察它被重建；紧接着 `cargo check`，解释第二次为什么快。
