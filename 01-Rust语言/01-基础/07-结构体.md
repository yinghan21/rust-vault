# 结构体

> [!abstract] 一句话
> 结构体（`struct`）把若干相关的值装进一个命名类型，每个字段都有名字和类型；它本身不含行为，行为写在 `impl` 块里（[[09-方法与 impl|方法与 impl]]）。

## 为什么需要它

C 的 `struct` 只是字段集合，函数要另写、指针要自己传；Java 的 `class` 把字段和方法绑在一起，却默认可变并带继承；Python 的 `dict` 灵活，写错 key 只有运行时才知道。Rust 把**数据定义**（`struct`/`enum`）和**行为**（`impl`）分开：字段布局清晰、可见性可逐项控制、还能用 `derive` 批量生成实现。

## 核心规则

### 定义与实例化

- 定义只描述「长什么样」，不分配内存：`struct User { active: bool, username: String, email: String }`。
- 实例化必须给出**所有**字段，顺序随意；`let mut u = User { ... }` 之后才能改字段，但「可变」属于整个实例，不能只声明某个字段可变。
- 字段类型随意，也可以是 `Box` 打破递归（`struct List { next: Option<Box<List>> }`）；访问用 `u.username`，字段默认私有，跨模块需要 `pub`（[[10-模块与可见性|模块与可见性]]）。

### 字段初始化简写与更新语法

- **简写**：变量名与字段名相同时写 `User { username, email }`，等价于 `username: username`。
- **更新语法**：`User { email: new, ..old }` 表示其余字段从 `old` 取。
- 更新语法**不是复制**：`..old` 会把没用到的字段**移动**过来，所以 `old` 之后不能再用；要继续用就写 `..old.clone()`（需要 `Clone`）。这是 [[05-所有权|所有权]] 里「部分移动」最常见的现场。

```rust
#[derive(Debug, Clone)]
struct User {
    username: String,
    email: String,
    active: bool,
}

fn main() {
    let username = String::from("alice");
    let u1 = User {
        username, // 简写：变量名与字段名相同
        email: String::from("alice@example.com"),
        active: true,
    };
    let u2 = User {
        email: String::from("alice@work.example"),
        ..u1.clone() // 其余字段来自 u1 的副本，u1 之后仍可用
    };

    println!("{:?}", u1);
    println!("{:?}", u2);
}
```

### 元组结构体与单元结构体

| 形式 | 写法 | 用途 |
| --- | --- | --- |
| 元组结构体 | `struct Meters(f64);` | 单个值加类型语义，字段用 `.0` 访问 |
| 单元结构体 | `struct Marker;` | 不存数据，只挂 trait 或做类型标记，大小为 0 |

元组结构体最经典的用法是 newtype：`Meters(f64)` 与 `Feet(f64)` 是两个不同类型，传错单位会直接编译失败，而裸 `f64` 之间混用编译器管不了。

### derive 与内存布局

| trait | 作用 | 备注 |
| --- | --- | --- |
| `Debug` | `{:?}` 打印 | 调试必备，几乎每个结构体都该有 |
| `Clone` / `Copy` | 显式复制 / 隐式复制 | `Copy` 要求所有字段都是 `Copy` |
| `PartialEq` / `Eq` | `==` / 全等 | 含 `f64` 的结构体只能 `PartialEq` |
| `PartialOrd` / `Ord` | 比较与排序 | `Ord` 是 `BTreeMap` key 的前提 |

`Display` 不能 derive，必须手写 `impl`（[[15-trait 基础|trait 基础]]）。

布局方面：默认 `repr(Rust)` 允许编译器**重排字段**以减少填充，尺寸不承诺；`#[repr(C)]` 严格按声明顺序排布，跨 FFI 传数据时必须加；`#[repr(transparent)]` 保证 newtype 与内部类型布局一致；`#[repr(packed)]` 去掉填充但字段可能非对齐，取引用即未定义行为。

## 代码示例

```rust
use std::mem::size_of;

// 元组结构体：用类型区分单位，避免「米 / 英尺」混用
struct Meters(f64);
struct Feet(f64);

// 单元结构体：不占空间，常用来做标记类型
struct Marker;

// derive：让编译器生成常用实现；Default 配合更新语法只写关心的字段
#[derive(Debug, Default, PartialEq, Eq, Clone, Copy)]
struct Version { major: u16, minor: u16 }

// repr(C)：按声明顺序布局，用于 FFI 或需要确定字节布局的场合
#[repr(C)]
#[derive(Debug)]
struct Packet { flag: u8, id: u32, kind: u16 }

fn total_meters(m: Meters, f: Feet) -> f64 {
    m.0 + f.0 * 0.3048
}

fn main() {
    println!("{:.2} 米", total_meters(Meters(100.0), Feet(3.0)));
    assert_eq!(size_of::<Marker>(), 0); // 单元结构体大小为 0

    // Default 配合更新语法，只写关心的字段
    let v = Version { major: 1, ..Default::default() };
    assert_eq!(v, Version { major: 1, minor: 0 });
    println!("{:?}，占 {} 字节", v, size_of::<Version>());

    // repr(C) 的具体尺寸与平台有关，这里只打印不断言
    let p = Packet { flag: 1, id: 7, kind: 2 };
    println!("{:?}，占 {} 字节", p, size_of::<Packet>());
}
```

## 常见错误与解决

| 错误 / 现象 | 原因 | 解决 |
| --- | --- | --- |
| `E0063: missing field 'email' in initializer` | 实例化时漏了字段 | 补上字段，或用 `..Default::default()` 填其余 |
| `E0560: struct 'User' has no field named 'mail'` | 字段名拼错或不属于该结构体 | 对照定义修正拼写 |
| `E0277: 'User' doesn't implement 'Debug'` | 用了 `{:?}` 却没 derive | 加 `#[derive(Debug)]` |
| `E0382: borrow of moved value: 'u1'` | `..u1` 把非 `Copy` 字段移走了 | 写 `..u1.clone()`，或调整后续使用顺序 |
| `E0308: expected 'f64', found 'Meters'` | 元组结构体与内部类型不是一回事 | 用 `m.0` 取值，或为 newtype 实现运算 |
| `E0451: field 'email' of struct 'User' is private` | 跨模块用字面量构造私有字段 | 提供 `pub fn new(...)`（见「模块与可见性」） |

## 练习

1. 定义 `Book { title: String, author: String, pages: u32 }`，写 `fn thicker<'a>(a: &'a Book, b: &'a Book) -> &'a Book`，返回页数更多的那个。
2. 用 `struct Celsius(f64)` 和 `struct Fahrenheit(f64)` 各写一个转换函数，试着把华氏度传进摄氏度函数，读一遍编译器给的 `E0308`。
3. 给自己定义的结构体加与不加 `#[repr(C)]`，用一个含 `u8`、`u32`、`u16` 字段的类型打印 `size_of`，解释差异来源。
