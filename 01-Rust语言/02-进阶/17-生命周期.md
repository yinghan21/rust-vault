# 生命周期

> [!abstract] 一句话
> 生命周期参数描述**引用之间的有效期关系**，纯粹是编译期信息；它不延长任何值的存在时间，只让编译器确认引用不会指向已释放的内存。

## 为什么需要它

[[06-借用与引用|借用]] 解决了「不能一边借用一边修改」，但还有一类问题：**返回的引用指向谁**。

```text
fn longest(x: &str, y: &str) -> &str {   // ❌ E0106: missing lifetime specifier
    if x.len() > y.len() { x } else { y }
}
```

编译器看到两个入参引用、一个返回值引用，没法判断返回值来自 `x` 还是 `y`，也就没法检查调用方是否在 `y` 释放后还使用它。生命周期标注就是把这一关系写清楚。C 里返回指向局部变量的指针是**未定义行为**，运行时才炸；Rust 在编译期就拒绝，代价是你要写几个 `'a`。

## 标注语法

```text
&'a T                       // 借用，生命周期为 'a
&'a mut T                   // 可变借用
Foo<'a>                     // 类型带生命周期参数
fn f<'a>(x: &'a str) -> &'a str
```

`'a` 不是一个具体时长，而是「一段区间」的代号。签名里的 `<'a>` 意思是「对**任意**生命周期 `'a` 都成立」：调用方选 `'a`，编译器检查它够不够用。

## 函数签名

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() >= y.len() { x } else { y }
}

fn main() {
    let a = String::from("比较长的");
    let b = "短";
    assert_eq!(longest(&a, b), "比较长的");

    let result;
    {
        let c = String::from("临时");
        result = longest(&a, &c); // 结果的生命周期被限制在 c 的作用域内
        assert_eq!(result, "比较长的");
    }
    // println!("{}", result); // ❌ E0597: c 已被释放，result 不能活得更久
}
```

关键理解：`'a` 取的是 `&a` 与 `&c` 生命周期的**交集**，所以 `result` 只能在 `c` 还活着时使用；标注并没有把 `c` 的生命周期「拉长」。

## 结构体中的引用

结构体只要存引用，就必须带生命周期参数，表示「它不能比借用的数据活得久」：

```rust
struct Excerpt<'a> { text: &'a str }

impl<'a> Excerpt<'a> {
    fn announce(&self) -> &str { self.text } // 省略规则 3：输出取 &self
    // 显式写 'a：返回值可以比 &self 借得久
    fn longer_than(&self, other: &'a str) -> &'a str {
        if self.text.len() > other.len() { self.text } else { other }
    }
}

fn main() {
    let novel = String::from("第一句。第二句。");
    let e = Excerpt { text: novel.split('。').next().unwrap() };
    assert_eq!(e.announce(), "第一句");
    assert_eq!(e.longer_than("x"), "第一句");
}
```

## 三条省略规则

绝大多数函数不用写 `'a`，编译器按这三条补：

1. **每个输入引用各得一个独立的生命周期参数**：`fn f(x: &str, y: &str)` → `fn f<'a, 'b>(x: &'a str, y: &'b str)`。
2. **只有一个输入生命周期时，输出取它**：`fn first_word(s: &str) -> &str`。
3. **有 `&self` / `&mut self` 时，输出取 `self` 的生命周期**：方法里返回的引用默认绑定到 `self`。

三条规则都不满足（两个入参 + 一个返回值）时，必须手写标注，否则报 `E0106`。

## `'static` 的误用

`'static` 表示「引用在整个程序运行期间都有效」，来源只有两种：编译进二进制的字面量，或主动泄漏的内存。

```rust
fn main() {
    let s: &'static str = "字面量存在二进制里，永不释放";
    assert!(s.starts_with("字面量"));
    let leaked: &'static str = Box::leak(String::from("泄漏").into_boxed_str());
    assert_eq!(leaked, "泄漏");
}
```

常见误用是把 `T: 'static` 当成「这个值活得很久」：

```text
fn bad() -> &'static str {
    let s = String::from("临时");
    &s            // ❌ E0515: cannot return reference to local variable
}

fn keep<T: 'static>(v: T) { /* ... */ } // T 内部不能含短生命周期的借用
```

`T: 'static` **不**要求值被泄漏，也不要求它活到程序结束，只要求它不含非 `'static` 的引用；`String`、`Vec<i32>` 都满足，而 `&'a str` 在 `'a` 不是 `'static` 时不满足。把参数写成 `T: 'static` 往往意味着设计有问题，先想想是否该用带生命周期的泛型。

## 常见错误与解决

| 错误 | 原因 | 解决 |
| --- | --- | --- |
| `E0106: missing lifetime specifier` | 多入参多返回值，无法推断 | 手写 `'a` 关联输入输出 |
| `E0515: cannot return reference to local variable` | 返回值指向函数内创建的数据 | 返回拥有所有权的值（`String`、`Vec`） |
| `E0597: does not live long enough` | 被借用的值先被释放 | 扩大被借用者作用域，或缩短借用 |
| `E0621: explicit lifetime required` | 签名缺约束，隐式要求 `'static` | 补 `'a`，或把所有权移入结构体 |

## 练习

1. 写 `fn longest_three<'a>(x: &'a str, y: &'a str, z: &'a str) -> &'a str`，说明为什么三者必须共用一个生命周期。
2. 判断能否编译并说明理由：`fn f<'a, T: 'a>(x: &'a T) -> &'a T { x }`。
