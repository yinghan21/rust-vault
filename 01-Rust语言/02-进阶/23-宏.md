# 宏

> [!abstract] 一句话
> 函数只能接固定个数、固定类型的值；宏接的是任意 token 并在编译期展开，所以 `vec![1, 2, 3]`、`matches!(x, Some(_))` 这类接口只能用宏写。

## 为什么需要它

函数做不到三件事：参数个数不定；需要看「语法形态」而不是值；需要在编译期生成代码。C 的 `#define` 也是文本替换，但连括号和类型都不管；Rust 的宏在 token / 语法树层面工作，展开结果照常参与类型检查。

## macro_rules! 基础

一条宏由若干「模式 => 替换」规则组成，按书写顺序尝试，第一条匹配成功的生效。模式里用 `$名字:说明符` 捕获 token，替换体里用 `$名字` 取回：

```rust
// 函数一次只能声明固定个数的参数，宏可以接任意个 token
macro_rules! max_of {
    ($x:expr) => { $x };
    ($x:expr, $($rest:expr),+) => {{
        let a = $x;
        let b = max_of!($($rest),+); // 宏可以递归调用自己
        if a > b { a } else { b }
    }};
}

fn main() {
    assert_eq!(max_of!(3), 3);
    assert_eq!(max_of!(3, 9, 2), 9);
}
```

## 片段说明符：决定「能匹配什么」

| 说明符 | 匹配 | 说明符 | 匹配 |
| --- | --- | --- | --- |
| `expr` | 表达式 | `ident` | 标识符或关键字 |
| `ty` | 类型 | `path` | 路径 `a::b::C` |
| `pat` | 模式 | `stmt` | 语句 |
| `tt` | 单个 token 树，最宽松 | `vis` | 可见性 `pub(crate)` |

`expr` 捕获到的是**一个完整语法单元**：`macro_rules! square { ($x:expr) => { $x * $x } }` 中 `square!(1 + 2)` 得到 `9`，而不是 `1 + 2 * 1 + 2`。换成 `tt` 就会按 token 替换，这是「说明符选错」类 bug 的根源。

## 重复：`$( ... )` 加分隔符

`$( ... )*` 零次或多次，`+` 一次或多次，紧跟的 `$(,)?` 吃掉尾随逗号。替换体里再写一遍 `$( ... )` 就逐项展开；多个捕获组可以并行重复（`$($k:expr => $v:expr),*`），这就是写「迷你 DSL」的方式。

```rust
macro_rules! my_vec {
    () => { Vec::new() };
    ($($x:expr),+ $(,)?) => {{
        let mut v = Vec::new();
        $( v.push($x); )+ // 每个捕获到的 $x 展开一次
        v
    }};
}

fn main() {
    let empty: Vec<i32> = my_vec![];
    assert!(empty.is_empty());
    assert_eq!(my_vec![1, 2, 3,], vec![1, 2, 3]); // 允许尾随逗号
}
```

## 卫生性（hygiene）

宏体内的 `let` 绑定带独立语法上下文，宏里的变量名不会和调用者的同名变量互相污染。这条规则只保护**绑定**，字段名、方法名、类型名不卫生，展开后仍要能解析到它们。跨 crate 导出宏还要用 `$crate` 代替 `crate`，它永远指向宏**定义**所在的 crate。

```rust
macro_rules! add_one {
    ($e:expr) => {{
        let tmp = $e; // 宏内的 tmp 与调用者的 tmp 是两个不同标识符
        tmp + 1
    }};
}

fn main() {
    let tmp = 100;
    assert_eq!(add_one!(tmp), 101);
    assert_eq!(tmp, 100); // 调用者的 tmp 完好无损
}
```

## 过程宏：必须独立 crate

过程宏接收 `TokenStream`、返回 `TokenStream`，只能定义在 `proc-macro = true` 的 crate 里，通常配合 `syn` 解析、`quote` 生成。**派生宏**只能追加 `impl`；**属性宏**能整体改写一个项；**函数式宏**形态最自由，适合内嵌 DSL。

```text
# Cargo.toml：宏 crate 必须是 proc-macro 类型
[lib]
proc-macro = true

# src/lib.rs
#[proc_macro_derive(Hello)]
pub fn hello_derive(input: TokenStream) -> TokenStream {
    let id = &syn::parse::<syn::DeriveInput>(input).unwrap().ident;
    quote::quote! { impl Hello for #id {} }.into()
}
```

## 何时不该用宏

| 需求 | 更该用的东西 |
| --- | --- |
| 参数类型不同、逻辑相同 | 泛型 + [[15-trait 基础\|trait 基础]] |
| 运行时多态 | [[16-trait 对象与动态分发\|trait 对象]] |
| 只是少写样板 | 函数、`impl`、`From` / `Default` |
| 要变长参数、要看语法结构 | 宏（它真正的强项） |

## 常见错误与解决

| 错误 | 原因 | 解决 |
| --- | --- | --- |
| `no rules expected the token ...` | 输入与所有规则都不匹配 | 检查分隔符，或加 `($($tt:tt)*)` 兜底分支 |
| `cannot find macro ... in this scope` | 宏定义在调用点之后，或未导出 | 定义提前，或加 `#[macro_export]` |
| 展开后报错指向宏内部 | 不卫生的字段名 / 方法名没解析到 | 用 `cargo expand` 看展开结果 |
