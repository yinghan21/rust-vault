# 迭代器

> [!abstract] 一句话
> `Iterator` 只有一个必需方法 `next()`：有元素返回 `Some(item)`，取完返回 `None`；`map`、`filter`、`collect` 全是在这个协议上搭出来的零成本抽象。

## 为什么需要它

手写循环把**遍历方式、筛选条件、结果收集**搅在一起，改一处需求就得动整个循环体。迭代器把「怎么遍历」交给容器（`IntoIterator`），把「拿元素干什么」交给适配器与消费器。相比 C 的 `for (i = 0; i < n; i++)`，边界与终止条件不再需要你保证；相比 Java Stream，适配器是惰性的，且优化后没有装箱与虚调用。

## 核心协议：`Iterator` 与 `next()`

[[iter.Iterator|Iterator]] 的全部义务只是实现一个方法，其余上百个方法都有默认实现。

```rust
fn main() {
    let v = vec![10, 20, 30];
    let mut it = v.iter(); // Item = &i32

    assert_eq!(it.next(), Some(&10));
    assert_eq!(it.next(), Some(&20));
    assert_eq!(it.next(), Some(&30));
    assert_eq!(it.next(), None); // 取完后一直返回 None
}
```

`next(&mut self)` 要求可变绑定：迭代器是**有状态的游标**，每次调用都推进内部位置；`size_hint` 让 `collect` 能预留容量。

## 惰性：适配器不干活，消费器才干活

`map`、`filter` 只构造新的迭代器结构体，一次循环都不跑：

```rust
fn main() {
    let v = vec![1, 2, 3, 4, 5];
    let lazy = v.iter().map(|x| {
        println!("计算 {}", x); // 不接消费器，这行永远不打印
        x * 2
    });
    let out: Vec<i32> = lazy.filter(|x| *x > 4).take(2).collect(); // 此刻才逐个求值
    assert_eq!(out, vec![6, 8]);
}
```

惰性的收益是**只算需要的部分**：`take(3)` 之后的元素不处理，`find` 找到就停，无限迭代器配合 `take` 也能安全使用。

## 适配器与消费器

| 类别 | 代表方法 | 说明 |
| --- | --- | --- |
| 转换 | `map`、`flat_map`、`copied`、`cloned` | 逐元素变换，返回新迭代器 |
| 筛选 | `filter`、`filter_map`、`take_while`、`skip_while` | 按条件保留或跳过 |
| 截取 | `take`、`skip`、`step_by`、`fuse` | 只处理一段，或标记「已结束」 |
| 组合 | `chain`、`zip`、`enumerate`、`peekable` | 拼接两个迭代器、附加下标 |
| 消费 | `collect`、`fold`、`sum`、`count`、`any`、`find`、`position`、`for_each`、`partition` | 真正开始循环并产出结果 |

链式顺序就是执行顺序：先 `filter` 淘汰，再 `map` 变换，`take` 拿够就停；把 `take` 放在 `map` 前面还能少算几次。

## 自定义迭代器

实现 `Iterator` 只需给出 `type Item` 和 `next`，让状态自己前进，不要预先缓存整个序列。

```rust
struct Countdown(u32);

impl Iterator for Countdown {
    type Item = u32;

    fn next(&mut self) -> Option<u32> {
        if self.0 == 0 {
            return None;
        }
        self.0 -= 1;
        Some(self.0 + 1)
    }
}

fn main() {
    let sum: u32 = Countdown(4).sum();
    assert_eq!(sum, 10); // 4 + 3 + 2 + 1

    let v: Vec<u32> = Countdown(3).collect();
    assert_eq!(v, vec![3, 2, 1]);
}
```

返回迭代器时具体类型（闭包包装是匿名类型）写不出来，用 `-> impl Iterator<Item = T>` 隐藏；想让自己的类型直接 `for`，实现 [[iter.IntoIterator|IntoIterator]]，给出 `type Item` 与 `type IntoIter` 即可。

## 与手写循环的性能对比

结论：**开启优化后两者通常一样快**。适配器链被单态化、内联成等价循环，不堆分配、不动态分发；真正拖慢速度的往往不是迭代器本身，而是多余的 `collect`、`iter()` 之后的 `clone`，以及 `Box<dyn Iterator>` 带来的动态分发。

```rust
use std::time::Instant;

fn main() {
    let data: Vec<u64> = (0..3_000_000).collect();

    let t = Instant::now();
    let mut manual = 0u64;
    for &x in &data { if x % 3 == 0 { manual += x; } }
    let manual_time = t.elapsed();

    let t = Instant::now();
    let iter_sum: u64 = data.iter().copied().filter(|x| x % 3 == 0).sum();
    let iter_time = t.elapsed();

    assert_eq!(manual, iter_sum); // 都是 O(n) 且不分配
    println!("手写 {:?}，迭代器 {:?}", manual_time, iter_time);
}
```

## 常见错误与解决

| 错误 | 原因 | 解决 |
| --- | --- | --- |
| `E0596: cannot borrow as mutable` | `next()` 需要 `&mut self` | 写成 `let mut it = ...` |
| `E0277: ... is not an iterator` | 对容器直接调适配器 | 先 `.iter()`、`.iter_mut()` 或 `.into_iter()` |
| `E0282: type annotations needed` | `collect()` 不知道收成什么 | `let v: Vec<_> = ...` 或 `.collect::<Vec<_>>()` |
| `E0502: cannot borrow as mutable` | 迭代期间修改容器 | 先 `collect()` 出新容器再改 |
| 闭包里 `x + 1` 类型不符 | `iter()` 给的是 `&i32` | 用 `copied()`/`cloned()`，或写 `\|&x\|` |
