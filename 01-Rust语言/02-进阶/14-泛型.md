# 泛型

> [!abstract] 一句话
> 泛型是「类型的参数」：写一次逻辑，编译器按实际类型生成多份具体代码（单态化），运行时因此不比手写重复代码慢。

## 为什么需要它

不用泛型，处理「取最大值」只有两条路：每种类型写一遍（`max_i32`、`max_f64`…，改一处漏三处），或用宏生成（可读性差、报错难定位，且没有类型检查）。泛型是第三条路：需要写 trait bound，但类型安全、运行时零开销。

| 语言 | 泛型实现 | 代价 |
| --- | --- | --- |
| Rust | 带约束的单态化 | 代码体积随实例数量增长 |
| C++ | 模板展开 | 没有 bound 检查，错误信息冗长 |

## 泛型函数

```rust
fn largest<T: PartialOrd + Copy>(list: &[T]) -> T {
    let mut max = list[0];
    for &item in list.iter() {
        if item > max { max = item; }
    }
    max
}

fn main() {
    assert_eq!(largest(&[3, 9, 2]), 9);
    assert_eq!(largest(&['a', 'z', 'm']), 'z');
}
```

`T` 是类型参数，`<T: PartialOrd + Copy>` 是约束（trait bound）：只有同时实现这两个 trait 的类型才能调用。`Copy` 之所以必要，是因为 `list[0]` 和 `max = item` 都按值取出。

## 泛型结构体与枚举

```rust
struct Point<T> { x: T, y: T }

// 约束多时也可以写成 where 子句，效果相同
impl<T> Point<T>
where
    T: std::fmt::Display,
{
    fn show(&self) -> String { format!("({}, {})", self.x, self.y) }
}

fn main() {
    let p = Point { x: 1, y: 2 };
    assert_eq!(p.show(), "(1, 2)");
}
```

枚举同理：`enum Either<L, R> { Left(L), Right(R) }`。标准库的 [[option.Option|Option]]、[[result.Result|Result]] 就是这个模式：类型参数 + 按约束分层的 `impl` 块。

## trait bound 与 where

约束多了以后尖括号会难读，用 `where` 把约束挪到签名下方（上面的 `impl` 块就是这种写法），含义完全相同；`impl<T: A> Trait for S<T>` 则是给泛型类型实现 trait。

## 单态化与代码膨胀

```rust
fn id<T>(x: T) -> T { x }

fn main() {
    // 二进制里其实有三个函数：id::<u8>、id::<u32>、id::<&str>
    assert_eq!((id(1u8), id(1u32), id("s")), (1, 1, "s"));
}
```

每个实际类型参数都生成一份独立机器码，这叫**单态化**（monomorphization）：调用点可以内联、没有虚表跳转；代价是体积随实例数增长、编译变慢。实例太多时可改接收 `&dyn Trait`，见 [[16-trait 对象与动态分发|trait 对象]]。

## const 泛型

```rust
fn sum<const N: usize>(arr: [i32; N]) -> i32 { arr.iter().sum() }

fn main() {
    assert_eq!(sum([1, 2, 3]), 6); // N = 3
}
```

`const` 参数只能是整数、`bool`、`char` 这类值；`N` 不同就各自生成一份代码，所以它同样走单态化。

## 泛型 vs `dyn`：怎么取舍

```rust
trait Shape { fn area(&self) -> f64; }

struct Circle(f64);
struct Square(f64);

impl Shape for Circle { fn area(&self) -> f64 { std::f64::consts::PI * self.0 * self.0 } }
impl Shape for Square { fn area(&self) -> f64 { self.0 * self.0 } }

// 静态分发：每种 T 生成一份代码，可内联
fn total_static<T: Shape>(shapes: &[T]) -> f64 { shapes.iter().map(|s| s.area()).sum() }
// 动态分发：只有一份代码，运行时查虚表
fn total_dyn(shapes: &[&dyn Shape]) -> f64 { shapes.iter().map(|s| s.area()).sum() }

fn main() {
    assert!((total_static(&[Circle(1.0), Circle(2.0)]) - 15.707_963).abs() < 1e-4);
    assert_eq!(total_dyn(&[&Square(2.0)]), 4.0);
}
```

| 维度 | `T: Trait` | `&dyn Trait` |
| --- | --- | --- |
| 调用开销 | 可内联，零开销 | 一次虚表查表，阻止内联 |
| 代码体积 | 每类型一份，会膨胀 | 只有一份 |
| 异构容器 | 一个容器只能放同一种 | 可以混放 |

经验法则：库内部实现、热点路径用泛型；需要「一个 `Vec` 放多种类型」或抑制代码膨胀时用 `dyn`。

## 常见错误与解决

| 错误 | 原因 | 解决 |
| --- | --- | --- |
| `E0277: the trait bound T: X is not satisfied` | 泛型体里用了 `X` 的方法却没加约束 | 在 `T:` 或 `where` 里补上 |
| `E0107: wrong number of generic arguments` | 泛型参数个数写错 | 补全参数，或用 `_` 让编译器推断 |
| `E0282` / `E0283` 推断不出 | 泛型返回类型缺少上下文 | turbofish 标注：`parse::<i32>()` |
| 编译变慢、二进制变大 | 单态化过度 | 把大函数下沉成 `&dyn Trait` |

## 练习

1. 把 `largest` 的约束改成只用 `PartialOrd`，说明为什么返回 `&T` 是唯一可行的改法。
2. 解释 `fn f<T>(x: T) { println!("{}", x); }` 为什么编译失败，缺了哪个约束。
