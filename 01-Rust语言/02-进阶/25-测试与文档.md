# 测试与文档

> [!abstract] 一句话
> 不需要 JUnit 或 pytest 那样的外部框架：`#[test]` 标函数、`cargo test` 跑用例，`///` 里的示例也会被编译并执行。

## 为什么需要它

Java、Python 里测一个函数要先选框架、配插件、写测试类，Rust 把这些内置了。真正的好处是**文档示例即测试**：示例和代码脱节就编译失败，「文档过期」立刻暴露。三类测试各管一段——单元测试在源码的 `#[cfg(test)] mod tests` 里，能访问私有项；集成测试在 `tests/`，每个文件是独立 crate，只看得到 `pub` API；文档测试来自 `///`，只验证公开接口。

## #[test] 与断言宏

测试就是一个返回 `()` 的函数，panic 即失败。三个断言宏都来自 [[macro.assert|assert]] 家族。

```rust
fn add(a: i32, b: i32) -> i32 { a + b }

#[test]
fn adds_two_numbers() {
    assert_eq!(add(2, 2), 4); // 相等
    assert_ne!(add(2, 2), 5); // 不等
    assert!(add(2, 2) > 3, "期望大于 3"); // 自定义失败信息
}

fn main() { assert_eq!(add(1, 1), 2); }
```

函数名要描述**行为**而不是编号：`adds_two_numbers` 比 `test1` 有用得多。浮点数不要用 `==`，比较 `(a - b).abs() < 1e-9`。

## should_panic：断言「它会崩」

有些函数违反契约时应该 panic，这时用 `#[should_panic]`；`expected` 是**子串匹配**，用来确认崩在正确的地方。

```rust
fn checked_div(a: i32, b: i32) -> i32 { assert!(b != 0, "除数不能为 0"); a / b }

#[test]
#[should_panic(expected = "除数不能为 0")]
fn panics_on_zero_divisor() { let _ = checked_div(1, 0); }

fn main() { assert_eq!(checked_div(4, 2), 2); }
```

不加 `expected` 时任何 panic 都算通过——包括你写错断言导致的 panic，所以建议总是带上。

## Result 测试：用 ? 代替 unwrap

测试函数可以返回 `Result`，`?` 遇到 `Err` 就失败并打印 `Debug`，比满屏 `unwrap()` 干净；错误类型不统一时写 `Box<dyn std::error::Error>`，见 [[11-错误处理|错误处理]]。

```rust
fn parse_port(s: &str) -> Result<u16, std::num::ParseIntError> { s.trim().parse() }

#[test]
fn parses_port() -> Result<(), Box<dyn std::error::Error>> {
    assert_eq!(parse_port(" 8080 ")?, 8080);
    Ok(())
}

fn main() { assert_eq!(parse_port("80").unwrap(), 80); }
```

## 单元测试：`#[cfg(test)] mod tests`

单元测试写在**同一个文件**里，`#[cfg(test)]` 保证它不进正式构建，`use super::*` 让它能访问私有项。

```rust
pub fn is_even(n: i32) -> bool { n % 2 == 0 }

#[cfg(test)]
mod tests {
    #[test]
    fn accepts_even() { assert!(super::is_even(4)); }
}

fn main() { assert!(is_even(2)); }
```

## 集成测试：`tests/` 目录

`tests/` 下**每个文件都是一个独立 crate**，链接你的库，所以只能用 `pub` API——这正是「从用户视角验证接口」的意义。

```text
my_crate/tests/
├── common/mod.rs      # 共享 helper：没有 #[test]，不会被当成用例
└── api.rs             # 一个文件 = 一个集成测试 crate
// tests/api.rs 里只能看见 pub API
use my_crate::is_even;
#[test]
fn public_api_works() { assert!(is_even(10)); }
```

`tests/common/mod.rs` 必须放在子目录里，否则它自己会被当成一个测试 crate 去跑。

## 文档测试：注释里的示例会被执行

`///` 中的示例会被 rustdoc 抽出来单独编译运行，`cargo test` 默认包含它们。

```rust
/// 把摄氏度转成华氏度。
///
/// 示例（真实文件里要把下面两行包在 rust 代码块中）：
/// let f = c_to_f(100.0);
/// assert!((f - 212.0).abs() < 1e-9);
pub fn c_to_f(c: f64) -> f64 { c * 9.0 / 5.0 + 32.0 }

fn main() { assert_eq!(c_to_f(0.0), 32.0); }
```

## cargo test 用法

| 命令 | 作用 |
| --- | --- |
| `cargo test` | 单元 + 集成 + 文档测试全跑 |
| `cargo test --lib` / `--test api` / `--doc` | 只跑单元 / 指定集成测试 / 文档测试 |
| `cargo test -- --nocapture` | 显示 `println!` 输出（默认被捕获） |

更多命令见 [[Cargo 速查|Cargo 速查]] 与 [[02-Cargo 与项目结构|Cargo 与项目结构]]。

## 常见错误与解决

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `0 passed; 0 failed` | 没有 `#[test]`，或在 `main.rs` 里却跑了 `--lib` | 加属性，确认测试所在 target |
| 集成测试 `unresolved import` | `tests/` 只看到 `pub` API | 把接口设为 `pub`，或用 `pub use` 重导出 |
| `#[should_panic]` 用例意外通过 | 根本没走到 panic 分支 | 检查分支；`expected` 只做子串匹配 |
