# 性能与优化

> [!abstract] 一句话
> 不测量的优化只是重写代码：先用 `cargo bench` / `perf` / flamegraph 找到那 3% 的热点，再让它**少一次分配、少一次克隆、多一次内联**。

## 为什么需要它

零成本抽象只保证抽象不额外收费，不保证你的代码免费：`clone()`、`format!`、`Vec` 反复扩容都是写在明面上的真实分配。C 的优化路径是抠内存布局，Python 的是换算法，Rust 落在中间——**抽象不慢，藏起来的分配才慢**。而直觉几乎总是错的，所以顺序永远是：量、改一处、再量。

## 先测量：cargo bench、perf、flamegraph

跑一次会被启动开销污染，要循环多次；结果喂给 `black_box`，否则整段循环会被优化成常量。

```rust
fn main() {
    let t = std::time::Instant::now();
    let sink: u64 = (0..1000).map(|_| std::hint::black_box((1..=1000u64).map(|x| x * x).sum::<u64>())).sum();
    println!("{:?} {}", t.elapsed(), sink); // 耗时依机器而定
}
```

正式基准用 criterion：`cargo add criterion --dev`，在 `Cargo.toml` 里声明一个 `bench` 目标并把默认的 libtest harness 关掉（`harness = false`），再跑 `cargo bench`；热点用 `perf record -g` 配 `perf report`，或 `cargo flamegraph` 直接出图；编译耗时看 `cargo build --timings`，体积看 `cargo bloat --release`。`Instant` 是单调时钟（[[time.Instant|Instant]]），而 `cargo run` 默认 debug、比 release 慢 10–100 倍，任何结论都必须来自 `--release` 或 `cargo bench`。

## 第一课：预留容量

`Vec::new()` 容量为 0，push 到第 1、2、4、8…… 个元素都要重新分配搬家；已知规模就一次分配到位，同款手法用于 `String::with_capacity`、`HashMap::with_capacity`，长期持有的结构瘦身用 `shrink_to_fit`（[[vec.Vec|Vec]]、[[12-集合类型|集合类型]]）。

```rust
fn main() {
    let mut slow = Vec::new();
    let mut fast = Vec::with_capacity(10_000);
    for i in 0..10_000 { slow.push(i); fast.push(i); }
    assert_eq!(slow, fast); // 内容相同
    assert!(fast.capacity() >= 10_000); // 只保证「至少」，实际通常正好
}
```

## 第二课：用借用代替 clone

能借就别复制：`iter().cloned()` 是真实的堆分配，而参数写 `&str` 比 `&String` 能接更多来源——字面量、`&String`、切片都行，容器同理写 `&[T]`、路径写 `&Path`，见 [[06-借用与引用|借用]]。

```rust
fn count_words(text: &str) -> usize { text.split_whitespace().count() }

fn main() {
    let names = vec![String::from("ada"), String::from("bob")];
    let copied: Vec<String> = names.iter().cloned().collect(); // ❌ 只为读长度就克隆
    let total: usize = names.iter().map(|s| s.len()).sum(); // ✅ 借用，零分配
    assert_eq!((copied.len(), total), (2, 6));

    let owned = String::from("rust is fast");
    assert_eq!(count_words(&owned), 3); // &String 自动解引用成 &str
    assert_eq!(count_words(&owned[0..4]), 1); // 切片也可以
}
```

循环里最危险的是 `format!`：每轮一次分配。改成 `write!` 写入复用缓冲区，日志用结构化字段而非先拼字符串（[[27-常用 crate 与生态|常用 crate 与生态]]）。

## 第三课：迭代器链编译出来就是循环

中间不产生临时 `Vec`；真正慢的是**链中间 `collect()` 出一个集合**，或在闭包里做分配。原理见 [[18-迭代器|迭代器]]。

```rust
fn main() {
    let data: Vec<u32> = (1..=10).collect();
    let chained: u32 = data.iter().map(|x| x * 2).filter(|x| x % 3 == 0).sum();
    let mut manual = 0;
    for x in &data { let y = x * 2; if y % 3 == 0 { manual += y; } }
    assert_eq!(chained, manual); // 单态化后是同一段机器码
}
```

## 第四课：内联与 LTO

小函数跨 crate 默认难内联——编译器只看得见当前 crate 的代码。源码级手段是 `#[inline]`（提示跨 crate 内联）与 `#[inline(always)]`（强行内联，放大体积、挤爆指令缓存，没有基准就别用）；冷分支函数加 `#[cold]`，本机指令集用 `RUSTFLAGS="-C target-cpu=native"`（二进制不再通用）。更省事的是改 release 配置：

```toml
[profile.release]
lto = "thin"        # 跨 crate 内联与死代码消除；"fat" 更彻底但更慢
codegen-units = 1   # 单代码单元：优化更狠、编译更久
panic = "abort"     # 去掉 unwind 表，体积更小
```

## 第五课：Box 与字符串拼接的分配账

栈和堆本身速度相近，差的是缓存局部性与分配次数：大而冷的枚举变体值得放 `Box`，给 `u32` 加 `Box` 只多一次分配和一次指针追逐。`Vec<T>` 是 3 个机器字、`&[T]` 是 2 个，见 [[boxed.Box|Box]]、[[20-智能指针|智能指针]]。

```rust
struct Big([u64; 512]); // 4 KiB
enum Node { Empty, Inline(Big), Boxed(Box<Big>) }

fn main() {
    assert!(std::mem::size_of::<Node>() >= 4096); // 一个 Inline 变体撑大整个枚举
    assert_eq!(std::mem::size_of::<Option<Box<u64>>>(), 8); // 非空指针优化，省掉 tag
}
```

`+` 会吃掉左操作数，`format!` 每次新建 `String`，循环里都是分配放大器，所以先算总长再一次分配；写文件套 [[io.BufWriter|BufWriter]]，见 [[13-字符串|字符串]]。

```rust
fn main() {
    let words = ["alpha", "beta", "gamma"];
    let mut slow = String::new();
    for w in words { slow.push_str(w); slow.push(' '); } // ❌ 多次扩容
    let cap: usize = words.iter().map(|w| w.len() + 1).sum();
    let mut fast = String::with_capacity(cap); // ✅ 只分配一次
    for w in words { fast.push_str(w); fast.push(' '); }
    assert_eq!(slow, fast);
}
```

## 常见误区

| 误区 | 真相 |
| --- | --- |
| 过早优化 | 先正确、可读，再按火焰图动手；凭直觉改的多半白改 |
| 靠 unsafe 提速 | 边界检查常被优化器消掉，而别名信息丢失让 LLVM 更保守，常见结果是更慢 |
| 在 debug 下比快慢 | 差 10–100 倍，结论不可迁移 |
| 迭代器比 for 慢 | 单态化后等价，慢的只是多余的 `collect` |
| 默认 HashMap 最快 | 默认哈希器抗 DoS 而非求快；热点表可换 `FxHashMap`/`ahash`，省内存用 `BTreeMap` |

## 练习

1. 用 `Instant` + `black_box` 对比 `Vec::new()` 与 `Vec::with_capacity(100_000)` 连续 push 的耗时。
2. 写 `fn join(words: &[&str], sep: &str) -> String`，先不预留容量跑 bench，再加 `with_capacity` 对比。
