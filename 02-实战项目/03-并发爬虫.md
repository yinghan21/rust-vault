# 项目：并发爬虫 title-crawler

## 目标

写一个 `title-crawler <URL>...`：一次给十几个地址，程序并发抓取并打印每页的 `<title>`；同时在飞的请求不超过 4 个，单个站点超时或返回 5xx 时重试 3 次，最终失败只打印一行不 panic。做完这一篇，`tokio` 任务、`Semaphore` 限流、`reqwest` 超时与重试四条线会串成一条能跑的流水线。

## 技术栈

| 用途 | crate / 标准库 |
| --- | --- |
| 异步运行时、并发任务、定时器 | `tokio`（`rt-multi-thread`、`macros`、`time`） |
| HTTP 客户端与连接池 | `reqwest` 0.12（`rustls-tls`，免 OpenSSL） |
| 从 HTML 里抠标题 | `regex` |
| 错误上下文与错误链 | `anyhow` |

## 第 1 步：初始化项目

```bash
cargo new title-crawler
cd title-crawler
cargo add tokio --features macros,rt-multi-thread,time
cargo add reqwest --no-default-features --features rustls-tls,gzip
cargo add regex anyhow
```

`Cargo.toml` 的完整依赖片段：

```toml
[package]
name = "title-crawler"
version = "0.1.0"
edition = "2021"

[dependencies]
anyhow = "1"
regex = "1"
reqwest = { version = "0.12", default-features = false, features = ["rustls-tls", "gzip"] }
tokio = { version = "1", features = ["macros", "rt-multi-thread", "time"] }
```

`reqwest` 默认用 native-tls，Linux 上要求系统装了 OpenSSL 开发包；换 `rustls-tls` 后 TLS 由 Rust 实现，交叉编译和静态链接都省事。`time` 特性必须有，否则 `tokio::time::sleep` 与 `timeout` 不存在。

## 第 2 步：并发骨架 —— JoinSet + Semaphore

```rust
use anyhow::{Context, Result};
use regex::Regex;
use std::sync::Arc;
use std::time::Duration;
use tokio::sync::Semaphore;
use tokio::task::JoinSet;

#[tokio::main]
async fn main() -> Result<()> {
    let urls: Vec<String> = std::env::args().skip(1).collect();
    if urls.is_empty() {
        anyhow::bail!("用法：title-crawler <URL>...");
    }
    // Client 内部是 Arc，clone 一份很便宜；连接池由所有任务共用
    let client = reqwest::Client::builder()
        .user_agent("title-crawler/0.1")
        .connect_timeout(Duration::from_secs(5)) // 连不上就别占着许可干等
        .build()?;
    let re = Regex::new(r"(?is)<title[^>]*>(.*?)</title>")?;
    // 同时最多 4 个请求在飞，其余任务在 acquire 上排队等待许可
    let sem = Arc::new(Semaphore::new(4));

    let mut set = JoinSet::new();
    for url in urls {
        set.spawn(crawl(url, client.clone(), re.clone(), Arc::clone(&sem)));
    }
    while let Some(joined) = set.join_next().await {
        match joined {
            Ok((url, Ok(title))) => println!("✓ {title}  <-  {url}"),
            Ok((url, Err(e))) => println!("✗ {url}：{e:#}"),
            Err(e) => eprintln!("任务异常退出：{e}"),
        }
    }
    Ok(())
}

/// 先拿到许可再抓取，函数返回时许可随 _permit 自动归还
async fn crawl(
    url: String,
    client: reqwest::Client,
    re: Regex,
    sem: Arc<Semaphore>,
) -> (String, Result<String>) {
    let _permit = sem.acquire_owned().await.expect("信号量不会被关闭");
    let title = fetch_title(&client, &re, &url).await;
    (url, title)
}
```

`JoinSet` 里的任务是 `'static` 的，所以参数要 `clone` 进去，不能用 `&url`；`acquire_owned` 需要 `Arc<Semaphore>`，而 `acquire()` 只能借用，没法跨任务持有一整轮。许可放在 `crawl` 里而不是 `main` 里，是为了让排队等待也算进任务生命周期，超时和日志都还看得到。

## 第 3 步：单次抓取 —— 超时 + 正则

```rust
async fn fetch_title(client: &reqwest::Client, re: &Regex, url: &str) -> Result<String> {
    let mut last_err = None;
    for attempt in 0..3 {
        match try_once(client, re, url).await {
            Ok(title) => return Ok(title),
            Err(e) => {
                // 指数退避：300ms、600ms、1200ms，避免连环撞墙
                let backoff = Duration::from_millis(300 * 2u64.pow(attempt));
                eprintln!("{url} 第 {} 次失败：{e}，{:?} 后重试", attempt + 1, backoff);
                tokio::time::sleep(backoff).await;
                last_err = Some(e);
            }
        }
    }
    Err(last_err.unwrap_or_else(|| anyhow::anyhow!("{url} 重试次数耗尽")))
}

async fn try_once(client: &reqwest::Client, re: &Regex, url: &str) -> Result<String> {
    let req = client.get(url);
    // connect_timeout 只管建连，整个请求的总时长由 tokio::time::timeout 兜底
    let fut = async {
        let resp = req.send().await?.error_for_status()?; // 4xx/5xx 变成 Err
        Ok::<_, anyhow::Error>(resp.text().await?)
    };
    let body = tokio::time::timeout(Duration::from_secs(10), fut)
        .await
        .map_err(|_| anyhow::anyhow!("{url} 超过 10s"))??;

    re.captures(&body)
        .and_then(|c| c.get(1))
        .map(|m| m.as_str().trim().to_string())
        .with_context(|| format!("{url} 里没有 <title>"))
}
```

正则 `(?is)` 是关键：`i` 让 `<TITLE>` 也匹配，`s` 让 `.` 跨行，标题写在多行时才抠得到。`error_for_status()` 把 404/503 提前转成错误，重试才有意义；不加它，`resp.text()` 会把错误页当成正文解析。

## 运行与验证

```bash
cargo run -- https://example.com https://www.rust-lang.org https://doc.rust-lang.org
cargo run -- $(cat urls.txt)      # 给 20 个地址，再把 Semaphore::new(4) 改成 1 和 16 各跑一次
```

正常输出是若干 `✓ 标题 <- 地址`；把地址改成 `https://httpbin.org/status/503` 可以看到三次重试日志和最终的 `✗`，而进程退出码仍是 0。20 个地址时，并发 1 的耗时约为并发 4 的 4 倍，这就是 `Semaphore` 在做限流；数字再往上加，收益会被目标站点的响应时间和本机带宽吃掉，所以 4–8 通常是最稳的区间。

## 扩展方向

1. 加 `--concurrency N` 与 `--timeout S` 两个参数，`Semaphore::new(n)` 在运行时决定（`clap` 见 [[01-命令行工具|命令行工具]]）。
2. 换成 `Stream` + `buffer_unordered`，边完成边打印，不用等全部任务结束。
3. 限制单域名并发（每个 host 一个 `Semaphore`），对目标站点更礼貌。
4. 用 `tracing` + `tracing-subscriber` 打印结构化日志，配合 `tracing-tree` 看每个请求的生命周期；耗时对比见 [[26-性能与优化|性能与优化]]。
