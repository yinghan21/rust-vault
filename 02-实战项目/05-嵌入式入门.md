# 项目：嵌入式入门 blinky

## 目标

在真实单片机上点亮一颗 LED：`#![no_std]`、`#![no_main]` 的入口，点灯逻辑只依赖 `embedded-hal` 的 `OutputPin` 和 `DelayNs` 两个 trait，板级细节关在 `main` 里；日志走 `defmt` 的 RTT 通道，由 `probe-rs` 解码并在终端打印。

> [!important] 这一篇离不开硬件
> 需要一块带调试探针的开发板（文中用 STM32F411 Nucleo，板载 ST-Link，LED 接 PA5）、`probe-rs` 和 ST-Link 驱动。没有板子也能读，但第 4 步之后的验证跑不了；无板子替代方案见「运行与验证」最后一节。

## 技术栈

| 用途 | crate / 工具 |
| --- | --- |
| 裸机启动、中断向量表、`#[entry]` | `cortex-m-rt` 0.7、`cortex-m` 0.7 |
| 引脚与延时的抽象层 | `embedded-hal` 1.0（`digital::OutputPin`、`delay::DelayNs`） |
| 具体芯片的外设与时钟 | `stm32f4xx-hal`（换板子就换成对应 HAL） |
| 日志：编译期压缩字符串 + RTT | `defmt` 0.3、`defmt-rtt` 0.4 |
| panic 处理与烧写/日志解码 | `panic-probe`、`probe-rs`（`cargo install probe-rs-tools`） |

## 第 1 步：工具链与硬件准备

```bash
rustup target add thumbv7em-none-eabihf   # Cortex-M4F，带硬件浮点
cargo install probe-rs-tools --locked     # 提供 probe-rs、cargo-flash
probe-rs list                             # 能列出 ST-Link 就说明驱动通了
probe-rs chip list | grep STM32F411       # Windows 下把 grep 换成 findstr
```

`thumbv7em-none-eabihf` 是 `stm32f411` 的 ABI；用 `thumbv6m-none-eabi`（Cortex-M0）会得到一堆链接错误。`probe-rs` 同时负责烧写和 RTT 解码，所以不再需要 OpenOCD + telnet 那一套。

## 第 2 步：项目骨架

从官方模板起步最省事，`memory.x`、`build.rs`、`.cargo/config.toml` 都是现成的：

```bash
cargo install cargo-generate
cargo generate --git https://github.com/rust-embedded/cortex-m-quickstart
# 模板里的 memory.x 按芯片改两行：FLASH 512K / RAM 128K
```

`Cargo.toml` 的依赖部分（版本以 crates.io 上最新为准；换芯片就把 HAL 换掉、`features` 里的型号换掉）：

```toml
[dependencies]
cortex-m = "0.7"
cortex-m-rt = "0.7"
panic-probe = { version = "0.3", features = ["print-defmt"] }
defmt = "0.3"
defmt-rtt = "0.4"
embedded-hal = "1.0"
stm32f4xx-hal = { version = "0.21", features = ["stm32f411", "rt"] }

[profile.release]
debug = 2      # 保留调试信息，panic 和 defmt 的栈才好读
```

`.cargo/config.toml` 里两处不能少：`runner` 让 `cargo run` 直接烧写并附着调试器，`-Tdefmt.x` 是 `defmt` 的链接期字符串表：

```toml
[build]
target = "thumbv7em-none-eabihf"

[target.thumbv7em-none-eabihf]
runner = "probe-rs run --chip STM32F411RETx"
rustflags = ["-C", "link-arg=-Tlink.x", "-C", "link-arg=-Tdefmt.x"]
```

## 第 3 步：可复用的点灯骨架

```rust
#![no_std]
#![no_main]

use defmt_rtt as _;    // 打开 RTT 传输，不留名字也要链接进来
use panic_probe as _;  // 提供 #[panic_handler]，并把 panic 打到 defmt

use embedded_hal::delay::DelayNs;
use embedded_hal::digital::OutputPin;

/// 只要求 P 能输出电平、D 能延时，所以换成任何 HAL 的引脚都能跑
pub struct Blinky<P, D> {
    pin: P,
    delay: D,
    half_period_ms: u32,
}

impl<P, D> Blinky<P, D>
where
    P: OutputPin,
    D: DelayNs,
{
    pub fn new(pin: P, delay: D, half_period_ms: u32) -> Self {
        Self { pin, delay, half_period_ms }
    }

    /// 翻转一次；错误类型来自 P::Error，由调用方决定怎么处理
    pub fn blink(&mut self) -> Result<(), P::Error> {
        self.pin.set_high()?;
        self.delay.delay_ms(self.half_period_ms);
        self.pin.set_low()?;
        self.delay.delay_ms(self.half_period_ms);
        Ok(())
    }
}
```

这段没有任何裸机概念：`DelayNs` 的 `delay_ms` 是阻塞忙等，`OutputPin` 的 `set_high` 返回 `Result`。`embedded-hal` 1.0 把错误类型做成了关联类型，所以 `blink` 必须把 `P::Error` 冒出去——这是它和 0.2 版最大的差别，旧教程直接 `set_high()` 不处理返回值，在 1.0 下编不过。

## 第 4 步：板级入口

同一份 `src/main.rs` 里接着写入口（`#![no_std]`、`#![no_main]` 仍在文件最上面）：

```rust
use cortex_m_rt::entry;
use stm32f4xx_hal::pac;

#[entry]
fn main() -> ! {
    let dp = pac::Peripherals::take().unwrap();
    let cp = cortex_m::Peripherals::take().unwrap();
    let clocks = dp.RCC.constrain().cfgr.freeze();      // 默认 16MHz HSI
    let gpioa = dp.GPIOA.split();
    let led = gpioa.pa5.into_push_pull_output();        // Nucleo 板 LD2 接 PA5
    let delay = cp.SYST.delay(&clocks);

    let mut blinky = Blinky::new(led, delay, 500);
    defmt::info!("开始闪灯：每 500ms 翻转一次");
    loop {
        // 引脚配置出错就没必要继续，panic 的位置由 panic-probe 打出来
        if blinky.blink().is_err() {
            panic!("GPIO 写入失败");
        }
    }
}
```

`main` 返回 `!`：裸机没有「退出」这回事，`endless loop` 就是这个程序的主体。`into_push_pull_output()`、`SYST.delay(&clocks)` 这类写法各 HAL、各版本有出入，编译报错时以 docs.rs 上你所用版本的 `split()` / `delay()` 签名为准，只改这一段，`Blinky` 不用动。

## 运行与验证

```bash
cargo build --release        # 先确认能编过
cargo run --release          # runner 会调 probe-rs：烧写 -> 复位 -> 附着 RTT
```

终端应打印出 `0.000000 INFO  开始闪灯：每 500ms 翻转一次`，板上 LED 以 1Hz 闪。日志来自 RTT 而不是串口，所以**拔掉调试器就再也看不到**，且必须用 `probe-rs run` 保持连接；只烧写不附着时用 `probe-rs download --chip STM32F411RETx target/thumbv7em-none-eabihf/release/blinky`。

LED 不闪的排查顺序：`probe-rs list` 有没有输出、`--chip` 名字对不对、`memory.x` 的 FLASH/RAM 是否是这块芯片的、PA5 是不是板子上 LED 的引脚（不同 Nucleo 型号不一样）。日志完全没有时先看 `.cargo/config.toml` 里 `-Tdefmt.x` 有没有漏。

没有开发板时可以先跑 QEMU 验证启动链路：`cortex-m-quickstart` 自带的 `qemu` 示例跑在 `lm3s6965evb` 上，`qemu-system-arm -cpu cortex-m3 -machine lm3s6965evb -nographic -semihosting-config enable=on,target=native -kernel <elf>` 能看到 `Hello, world!`，但那块板子没有真实 GPIO，点灯只能上真硬件。

## 扩展方向

1. 换成 `embassy` 的 `async` 执行器，用 `Timer` 代替 `delay_ms` 忙等，CPU 可以进低功耗。
2. 用 `embedded-hal` 的 `SpiDevice` / `I2c` 接一个传感器，把读数通过 `defmt` 打出来。
3. 用 `defmt` 的 `#[derive(Format)]` 给自定义结构体加日志格式，比手拼字符串省 flash。
4. 加 `cargo-hf2` 支持 UF2 拖拽烧写；CI 里只跑 `cargo build` 验证编译，硬件测试留给本地。
