# 写作规范（内部）

> [!warning] 这是给「写笔记的人（或 AI）」看的约定
> 读者是中文 Rust 学习者。所有正文用中文，标识符、类型名、函数名、宏名保留英文原文。

## 1. 文件与命名

| 内容 | 位置 | 文件名 |
| --- | --- | --- |
| 学习笔记 | `01-Rust语言/01-基础/`、`01-Rust语言/02-进阶/` | `05-所有权.md`（两位序号 + 主题） |
| 实战项目 | `02-实战项目/` | `01-命令行工具.md` |
| 速查 / 面试 | `03-速查与面试/` | `语法速查.md` |
| std 模块页 | `10-标准库std/模块/` | 模块名，如 `fs.md`、`collections.md` |
| std 条目页 | `10-标准库std/类型/` 等分类目录 | `模块.条目.md`，如 `option.Option.md`、`fs.File.md` |

- 文件名不加空格（中文可以）；不要用 `? * : " < > |`。
- std 条目页的文件名 = 库内路径去掉 `std::`，例如 `std::collections::HashMap` → `collections.HashMap.md`。
- 基础类型页写作 `primitive.str.md`、`primitive.slice.md`；整数合并页 `primitive.整数类型.md`，浮点合并页 `primitive.浮点类型.md`。

## 2. frontmatter

每个笔记都必须以 YAML frontmatter 开头。值里出现 `:`、`#`、`[`、`{` 时整体加双引号。

### 通用字段

```yaml
---
title: "标题（含 std:: 前缀，或中文主题）"
type: 学习笔记 | std-模块 | std-条目 | 实战项目 | 速查 | meta
tags:
  - rust/基础
aliases:
  - 短名
一句话: 一句话说明这个笔记解决什么问题。
updated: 2025-01-01
---
```

`aliases` 用于让 `[[所有权]]`、`[[Option]]` 这样的短链接生效；**除 meta 外每篇都要有**，且全库唯一。

### std 模块页额外字段

```yaml
type: std-模块
module: fs
stable: "1.0.0"        # 没有就写 ""
unstable: false
```

### std 条目页额外字段

```yaml
type: std-条目
kind: 结构体 | 枚举 | 特质 | 原始类型 | 类型别名 | 函数 | 宏
module: option
slug: option.Option
stable: "1.0.0"
```

### 学习笔记额外字段

```yaml
type: 学习笔记
stage: 入门 | 基础 | 进阶
order: 5
```

### 项目页额外字段

```yaml
type: 实战项目
difficulty: 入门 | 中等 | 进阶
stack: [cargo, clap, serde]
```

## 3. 标签

层级标签，最多两层，从下面选：

- `rust/入门`、`rust/基础`、`rust/进阶`、`rust/实战`
- `std/模块`、`std/类型`、`std/集合`、`std/IO`、`std/并发`、`std/特质`、`std/宏`、`std/时间`、`std/错误`
- `速查`、`面试`、`meta/规范`

## 4. 标准结构

### 4.1 学习笔记

```markdown
# 标题

> [!abstract] 一句话
> ……

## 为什么需要它
## 核心规则（或语法）
## 代码示例
## 常见错误与解决
## 练习
## 相关
```

「为什么」要讲清楚它解决了什么问题（最好和 C/C++/Java/Python 对比一句）。

### 4.2 std 模块页

```markdown
# std::fs

> [!abstract] 一句话
> ……

## 模块简介
（2–4 段，讲清楚这个模块负责什么、什么时候用）

## 快速上手
（一个可运行的最小示例）

## 常用条目
| 条目 | 说明 |
| --- | --- |
| [[fs.File|File]] | …… |

## 注意事项
（平台差异、性能、常见坑）

## 相关
（相邻模块、学习笔记）
```

> [!important] 不要写「全部条目」小节
> 构建脚本会自动在文末追加「全部条目」表格（含官方链接），你只写上面这些内容。

### 4.3 std 条目页

```markdown
# `Option<T>`

> [!abstract] 一句话
> ……

## 简介
## 常用方法 / 变体 / 关联项
（按功能分组的小节，每组一张表）
## 示例
## 常见陷阱
## 相关
```

方法表统一两列或三列：

| 方法 | 说明 |
| --- | --- |
| `is_some()` | 是否为 `Some`。 |

签名必须与「数据源」一致（`data/` 里提取的官方签名），不要凭记忆改写；方法表里写**方法名**即可，签名太长的放在表前的代码块里。

### 4.4 实战项目页

项目目标 → 技术栈 → 分步实现（每步带代码/命令）→ 运行与测试 → 扩展方向。

### 4.5 速查页

尽量用表格 + 短代码块，一屏能查完；不要大段散文。

## 5. 链接规则（最容易出错）

- 链接到 **学习笔记** 用别名或文件名：`[[所有权]]`、`[[05-所有权]]`。
- 链接到 **std 条目**：`[[option.Option|Option]]`、`[[collections.HashMap|HashMap]]`、`[[primitive.str|str]]`。
- 链接到 **std 模块**：`[[fs|std::fs]]`、`[[collections|std::collections]]`。
- 链接到 **项目/速查**：`[[01-命令行工具|命令行工具]]`。
- **只链接本库中确实存在的笔记**。不确定是否存在时，用行内代码 `` `std::process::abort` `` 并给出官方链接，不要凭空 `[[...]]`。
- 每篇至少 3 个出链；std 条目页必须回链所属模块页。

官方链接格式：`https://doc.rust-lang.org/std/<路径>`，例如
`https://doc.rust-lang.org/std/option/enum.Option.html`。

## 6. 语言风格

- 正文全中文；API 名、类型名、crate 名保留英文，放进行内代码。
- 术语统一：所有权、借用、生命周期、特质（trait）、泛型、模式匹配、智能指针、迭代器、闭包、宏、并发、异步、方法、关联函数、关联类型、孤儿规则、解引用强制转换、零成本抽象。
- 不要直译长句；英文原文的「Returns true if…」→「当……时返回 `true`」。
- 每个方法说明控制在一行（≤ 40 字），动词开头：返回 / 创建 / 判断 / 追加 / 删除 / 转换为 / 迭代 / 保留 / 消耗。
- 不要保留整段英文文档；不要出现「本文由 AI 生成」之类的句子。

## 7. 代码规范

- 所有 ```rust 代码块必须能独立通过 `rustc --edition 2021` 编译（库或二进制均可，脚本会逐个检查）。
- 需要 `main` 的就写 `fn main()`；需要 `?` 的写 `fn main() -> Result<(), Box<dyn std::error::Error>>`。
- 只用标准库，不引入外部 crate；不写 `ignore`、`no_run`、`compile_fail` 标记。
- 用 `assert_eq!` / `println!` 展示结果；注释用中文。
- 不要用 `#` 开头的隐藏行（rustdoc 专属写法），直接写完整代码。
- 示例尽量短：一个代码块解决一个知识点。

## 8. 表格

- 表头固定：`| 方法 | 说明 |` 或 `| 条目 | 说明 |`。
- 单元格里不要放换行；代码用反引号；竖线 `|` 要转义成 `\|`。
- 行数多时按功能拆成多张表，并在表前加小标题（`### 构造`）。

## 9. 不要做的事

- 不要编造不存在的 API、方法签名、稳定版本号。
- 不要复制官方文档整段英文；不要写「TODO」「待补充」。
- 不要修改 `10-标准库std/模块/*.md` 末尾由脚本生成的「全部条目」区块。
- 不要在正文里写相对路径或本地绝对路径。
