# std::i16

> [!abstract] 一句话
> `std::i16` 是 16 位有符号整数类型的「常量模块」：只有 `MIN`、`MAX` 两个已弃用的常量。

## 模块简介

`std::i16` 是个**冗余模块**：它不定义类型，只把 `i16` 的取值边界 `MIN`（-32768）和 `MAX`（32767）以模块路径的形式再导出一遍，早年可以写 `std::i16::MAX`。这两个常量现已标记 `deprecated`，官方建议改成原始类型上的关联常量 `i16::MIN` / `i16::MAX` / `i16::BITS`，值完全一样，新代码没有必要再碰 `std::i16` 这条路径。

**整数类型的方法不在本模块里。** 溢出检查、字符串解析、字节序转换、位运算等能力都定义在原始类型 `i16` 上，见[[primitive.整数类型|整数类型]]页面：`i16::checked_mul`、`i16::from_str_radix`、`i16::to_be_bytes` 等等。本页只负责说明模块里那两个常量。

`i16` 占 2 字节，取值范围 `-32768..=32767`。它常见于音频采样（16 bit PCM）、传感器读数、需要和 C 语言 `short` 对齐的 FFI 结构体，以及内存比精度更重要的有符号小字段。一旦涉及累加或乘法，先想想会不会超过 3 万，否则升级到 `i32` 更省心。

## 快速上手

```rust
fn main() {
    // 模块常量：已弃用的旧路径
    #[allow(deprecated)]
    let old_min = std::i16::MIN;
    assert_eq!(old_min, -32_768);

    // 推荐写法：原始类型上的关联常量
    assert_eq!(i16::MIN, -32_768);
    assert_eq!(i16::MAX, 32_767);
    assert_eq!(i16::BITS, 16);

    // 按进制解析（支持 2..=36）
    assert_eq!(i16::from_str_radix("7fff", 16).unwrap(), 32_767);
    assert_eq!("-42".parse::<i16>().unwrap(), -42);

    // 从更宽的整数安全收窄：越界返回 Err
    assert_eq!(i16::try_from(1_000i32).unwrap(), 1_000);
    assert!(i16::try_from(40_000i32).is_err());

    // 字节序转换与位运算
    assert_eq!((-1i16).to_be_bytes(), [0xff, 0xff]);
    assert_eq!(i16::from_be_bytes([0x12, 0x34]), 0x1234);
    assert_eq!(5i16.count_ones(), 2);

    println!("i16 范围 = {} ..= {}", i16::MIN, i16::MAX);
}
```

## 常用条目

| 条目 | 说明 |
| --- | --- |
| `std::i16::MIN` | 最小值 `-32768`，模块路径已弃用。 |
| `std::i16::MAX` | 最大值 `32767`，模块路径已弃用。 |
| `i16::MIN` / `i16::MAX` | 推荐写法：原始类型上的取值边界。 |
| `i16::BITS` | 位宽，恒为 `16u32`。 |
| `i16::from_str_radix` | 按指定进制解析字符串，越界报错。 |
| `i16::checked_mul` / `checked_div` | 溢出或除零时返回 `None`。 |
| `i16::saturating_sub` | 溢出时钳制到 `MIN` / `MAX`。 |
| `i16::wrapping_neg` | 回绕取负，对 `MIN` 不会 panic。 |
| `i16::try_from` | 从 `i32`、`u16` 等安全收窄。 |
| `i16::to_le_bytes` / `from_le_bytes` | 与小端字节数组互转，常见于二进制协议。 |
| `i16::swap_bytes` | 交换高低字节，处理设备端序差异。 |
| `i16::abs` / `unsigned_abs` | 取绝对值；后者对 `MIN` 也安全。 |

## 注意事项

> [!warning] 模块常量已弃用
> `std::i16::MIN` 与 `std::i16::MAX` 都会触发 `deprecated` 警告，直接用 `i16::MIN` 即可。`BITS` 只存在于原始类型上，模块里查不到。

> [!danger] `MIN` 是绝对值陷阱
> `-32768i16` 的绝对值超出 `i16` 范围，`i16::MIN.abs()` 在 debug 下 panic，`-i16::MIN` 重新赋值也一样。需要绝对值时，若只用于比较大小，用 `unsigned_abs()` 得到 `u16`；若必须留在 `i16`，用 `saturating_abs()`。

> [!tip] 与 C 的 `short` 对齐
> `std::os::raw::c_short` 在主流平台上就是 `i16`，写 FFI 结构体时可以直接用 `i16` 保证布局；反过来，从字节流解析出的数据记得确认端序，先 `from_be_bytes` / `from_le_bytes` 再参与运算。
