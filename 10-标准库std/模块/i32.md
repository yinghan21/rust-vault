# std::i32

> [!abstract] 一句话
> `std::i32` 是 32 位有符号整数类型的「常量模块」：只有 `MIN`、`MAX` 两个已弃用的常量。

## 模块简介

`std::i32` 是个**冗余模块**，本身不定义任何类型，只是把 `i32` 的边界 `MIN`（-2147483648）和 `MAX`（2147483647）用模块路径再导出一遍，让早年代码能写 `std::i32::MAX`。这些模块常量现在处于 `deprecated` 状态，官方推荐直接用原始类型上的关联常量：`i32::MIN`、`i32::MAX`、`i32::BITS`。

**整数类型的方法不在本模块里。** 解析、溢出检查、字节序转换、位运算全部定义在原始类型 `i32` 上，属于[[primitive.整数类型|整数类型]]页面的内容，例如 `i32::checked_add`、`i32::from_str_radix`、`i32::to_le_bytes`。本页只讲模块里的那两个常量。

`i32` 是 Rust 的**默认整数类型**：写 `let n = 42;` 而不加后缀，`n` 就是 `i32`。它占 4 字节，范围约 ±21 亿，覆盖绝大多数计数、金额（以分为单位）、枚举判别值等场景，也是与 C 的 `int` 交互时的首选类型。

## 快速上手

```rust
fn main() {
    // 模块常量：已弃用的旧路径
    #[allow(deprecated)]
    let old_max = std::i32::MAX;
    assert_eq!(old_max, 2_147_483_647);

    // 推荐写法：原始类型上的关联常量
    assert_eq!(i32::MIN, -2_147_483_648);
    assert_eq!(i32::MAX, 2_147_483_647);
    assert_eq!(i32::BITS, 32);

    // 宽化转换（i32 -> i64）不会丢信息
    let wide: i64 = i32::MAX as i64;
    assert_eq!(wide, 2_147_483_647);

    // 溢出：wrapping 回绕，checked 返回 None，默认在 debug 下 panic
    assert_eq!(i32::MAX.wrapping_add(1), i32::MIN);
    assert_eq!(i32::MAX.checked_add(1), None);
    assert_eq!(i32::MIN.unsigned_abs(), 2_147_483_648u32);

    assert_eq!(i32::from_str_radix("ff", 16).unwrap(), 255);
    println!("i32 范围 = {} ..= {}", i32::MIN, i32::MAX);
}
```

## 注意事项

> [!warning] 模块常量已弃用
> `std::i32::MAX` 之类会触发 `deprecated` 警告；同类信息现在挂在原始类型上（`i32::MAX`、`i32::BITS`），模块里没有 `BITS`。

> [!danger] 默认整数推断的坑
> 整数字面量默认推断为 `i32`：`let x = 3_000_000_000;` 会直接编译错误（超出 `i32` 范围），需要显式写成 `3_000_000_000i64`。反过来，`i32 as u32` 保留位模式，负值会变成接近 `u32::MAX` 的大数，跨符号转换请用 `try_from`。

> [!tip] 与 C 的 `int` 对齐
> `std::os::raw::c_int` 在主流平台就是 `i32`。若要把 `i32` 传给接受 `c_int` 的 FFI 函数，直接传即可；反之从 C 拿回的 `c_int` 也可以当 `i32` 用，不要假设它是 64 位。
