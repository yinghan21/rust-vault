# std::i64

> [!abstract] 一句话
> `std::i64` 是 64 位有符号整数类型的「常量模块」：只有 `MIN`、`MAX` 两个已弃用的常量。

## 模块简介

`std::i64` 是个**冗余模块**，只把 `i64` 的边界 `MIN`（-9223372036854775808）和 `MAX`（9223372036854775807）以模块路径导出，供旧代码写 `std::i64::MAX`。这些常量已被标记 `deprecated`，新代码请直接用原始类型上的关联常量 `i64::MIN` / `i64::MAX` / `i64::BITS`。

**整数类型的方法不在本模块里。** 溢出检查、字符串解析、字节序转换都在原始类型 `i64` 上，见[[primitive.整数类型|整数类型]]页面：`i64::checked_add`、`i64::from_str_radix`、`i64::to_be_bytes` 等。本页只负责模块里那两个常量。

`i64` 占 8 字节，范围约 ±9.22×10¹⁸。它是几个常见场景的默认选择：Unix 时间戳（秒或纳秒）、文件大小、数据库自增主键、以及任何需要跨平台固定 64 位的数值。在 32 位平台上它不会被自动降级，这一点和 `isize` 不同。

## 快速上手

```rust
fn main() {
    // 模块常量：已弃用的旧路径
    #[allow(deprecated)]
    let old_min = std::i64::MIN;
    assert_eq!(old_min, -9_223_372_036_854_775_808);

    // 推荐写法：原始类型上的关联常量
    assert_eq!(i64::MIN, -9_223_372_036_854_775_808);
    assert_eq!(i64::MAX, 9_223_372_036_854_775_807);
    assert_eq!(i64::BITS, 64);

    // 常见用途：纳秒时间戳
    let nanos_per_sec: i64 = 1_000_000_000;
    assert_eq!(nanos_per_sec * 60, 60_000_000_000);

    // u64 -> i64：as 静默回绕，try_from 会报错
    assert_eq!(u64::MAX as i64, -1);
    assert!(i64::try_from(u64::MAX).is_err());

    assert_eq!(1i64 << 40, 1_099_511_627_776);
    assert_eq!((1i64 << 40).count_ones(), 1);
    println!("i64 范围 = {} ..= {}", i64::MIN, i64::MAX);
}
```

## 注意事项

> [!warning] 模块常量已弃用
> `std::i64::MIN` 等写法会触发 `deprecated` 警告，改为 `i64::MIN`。千万别和 `i64::BITS` 混淆——后者只存在于原始类型。

> [!danger] `as` 会静默截断
> `u64::MAX as i64` 结果是 `-1`，`i128 as i64` 更是直接丢掉高位，编译器只在明显常量溢出时警告。只要来源可能越界，就用 `i64::try_from(x)?`；只有确定在范围内（例如已知 `u32`）才用 `as`。

> [!tip] 时间与大小别用 `i32`
> `std::time::SystemTime` 转出的秒数、`fs::Metadata::len()` 返回的文件大小都可能是 `u64` 量级，用 `i32` 接会立刻溢出。同理，纳秒时间戳从 1970 数起已经超过 10¹⁸ 的三分之一，务必用 `i64` 并考虑 `checked_*`。
