# std::u64

> [!abstract] 一句话
> `std::u64` 是 64 位无符号整数的「常量模块」：只有 `MIN`、`MAX` 两个常量，官方已建议改用原始类型上的关联常量。

## 模块简介

`std::u64` 是个**冗余模块**：它不定义类型，只把 `u64` 的取值边界挂成模块路径 `std::u64::MIN` / `std::u64::MAX`。这两个常量已被标注「未来版本弃用」，现在引用只报 `deprecated` 警告，将来会变成硬错误；新代码直接写 `u64::MIN` / `u64::MAX`。

**整数的方法不在这个模块里。** 溢出检查、进制解析、位运算、字节序转换全部定义在原始类型 `u64` 上，属于[[primitive.整数类型|整数类型]]页面的内容 —— 例如 `u64::checked_add`、`u64::wrapping_mul`、`u64::from_str_radix`、`u64::to_be_bytes`。位宽 `BITS` 也只在原始类型上有。所以本页只讲那两个常量，其余请移步该页。

`u64` 占 8 字节，范围 `0..=18446744073709551615`，是三个高频场景的默认选择：**时间戳**（`Duration::as_secs` 返回的就是 `u64`）、**哈希值**（`DefaultHasher` 的输出是 `u64`）、**ID 与文件大小**。在 64 位平台上 `usize` 也是 64 位，但 32 位平台上 `usize` 只有 32 位，所以需要跨平台固定的 64 位量时（文件头、协议字段、序列化）必须显式写 `u64`。

## 快速上手

```rust
use std::time::{Duration, SystemTime, UNIX_EPOCH};

fn main() {
    #[allow(deprecated)]
    let legacy_max = std::u64::MAX;
    assert_eq!(legacy_max, 18_446_744_073_709_551_615);

    assert_eq!(u64::MIN, 0);
    assert_eq!(u64::MAX, 18_446_744_073_709_551_615);
    assert_eq!(u64::BITS, 64);

    // 时间戳：时长换算成整秒就是 u64
    let d = Duration::from_millis(1_500);
    assert_eq!(d.as_secs(), 1);
    let secs: u64 = SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .expect("系统时钟早于 UNIX_EPOCH")
        .as_secs();
    assert!(secs > 1_600_000_000);

    // 哈希值、ID 常用 u64 承载
    let id = 0xDEAD_BEEF_u64;
    assert_eq!(id.count_ones(), 24);
    assert_eq!(id.to_be_bytes().len(), 8);

    // 加宽用 From，收窄用 TryFrom
    assert_eq!(u64::from(u32::MAX), 4_294_967_295);
    assert_eq!(u64::from(0xFFu8), 255);
    assert!(u8::try_from(300u64).is_err());

    println!("u64 范围 = {} ..= {}", u64::MIN, u64::MAX);
}
```

## 常用条目

| 条目 | 说明 |
| --- | --- |
| `std::u64::MIN` | 最小值 `0`，模块路径已标记为待弃用。 |
| `std::u64::MAX` | 最大值 `18446744073709551615`，模块路径已标记为待弃用。 |
| `u64::MIN` / `u64::MAX` | 推荐写法：原始类型上的取值边界。 |
| `u64::BITS` | 位宽，恒为 `64u32`；模块里没有这个常量。 |
| `u64::from(u32)` | 无符号加宽，编译期就能保证不失败。 |
| `u64::to_be_bytes` / `from_be_bytes` | 与八字节大端数组互转，序列化常用。 |
| `u64::from_str_radix` | 解析十六进制，例如 `"deadbeef"`。 |
| `u64::checked_add` / `checked_mul` | 溢出返回 `None`，安全累加计数。 |
| `u64::wrapping_mul` / `saturating_mul` | 回绕 / 钳制，混洗哈希值常用。 |
| `u64::swap_bytes` / `to_le` | 反转字节序，适配不同端序的文件格式。 |
| `u64::count_ones` / `leading_zeros` | 位计数与前导零个数。 |
| `u64::trailing_zeros` | 末尾零个数，可反推最低置位的位置。 |
| `u64::is_power_of_two` | 是否为 2 的幂。 |
| `u64::try_from` | 由 `u128` 等更宽类型收窄，越界返回 `Err`。 |

## 注意事项

> [!warning] 模块常量行将弃用
> `std::u64::MIN` / `std::u64::MAX` 会触发 `deprecated` 警告，官方计划在未来版本移除。新代码写 `u64::MIN` / `u64::MAX`；模块里也没有 `BITS` 这个常量。

> [!danger] 哈希值不稳定
> `u64` 常用来存哈希，但标准库不保证同一份数据在不同 Rust 版本、不同平台上算出同一个 `u64`（`HashMap` 默认还带随机种子）。要把哈希写进文件或协议，请选定一个固定算法自己算，别依赖 `DefaultHasher` 的结果。

> [!tip] 时间戳精度够不够
> 秒级时间戳用 `u64` 绰绰有余；精确到纳秒时 `u64` 只能覆盖约 585 年，超出就溢出。需要大范围的纳秒量用 `u128`（`Duration::as_nanos` 的返回类型正是 `u128`）。另外 32 位平台上别把 `usize` 和 `u64` 混用，`v.len() as u64` 安全，反向的 `as usize` 会截断。
