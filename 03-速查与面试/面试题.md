## 一、基础

### 1. `let`、`let mut`、`const`、`static` 有什么区别？

- `let` 绑定默认不可变，`let mut` 才可重新赋值；可变性属于**绑定**，不属于类型。
- `const` 是编译期常量，必须标注类型，可以出现在任意作用域，会被内联，没有固定地址。
- `static` 有固定内存地址，可为 `&'static` 引用，读写需要 `unsafe`（`static mut`）或同步原语。
- `const` 可参与常量求值（如数组长度），`static` 不能。

### 2. `String` 和 `&str` 的区别？

- `String` 是拥有所有权的可增长堆缓冲区（指针 + 长度 + 容量），`&str` 是借用的 UTF-8 视图（指针 + 长度）。
- 函数入参优先 `&str`，因为 `&String` 会自动解引用强制转换，反之不成立。
- `&str` 可以指向字符串字面量（`'static`）、`String` 的一部分或 `&[u8]` 转换结果。
- 拼接 `String + &str` 会移动左侧缓冲区，可能重新分配；多次拼接用 `push_str` 或 `format!`。

### 3. Rust 没有 `null`，那怎么表示「可能没有值」？

- 用 `Option<T>` 枚举，`Some(v)` 与 `None`，编译器强制处理两个分支。
- `Option<&T>`、`Option<Box<T>>`、`Option<NonZeroU32>` 等能借助空指针/零值优化，内存布局与裸指针等价。
- 错误用 `Result<T, E>`，与「缺失」区分开；`?` 让错误向上冒泡而不丢上下文。
- 好处是把空值检查从运行时移到编译期，不需要 `NullPointerException` 这类防御。

### 4. 数组、切片、`Vec` 的关系？

- `[T; N]` 是定长数组，长度是类型的一部分，存栈上（或随结构体布局）。
- `&[T]` 是切片引用（指针 + 长度），可指向数组、`Vec` 或其中一段。
- `Vec<T>` 拥有堆缓冲区，有长度与容量之分，`&vec[..]` 得到切片。
- 函数签名用 `&[T]` 最通用，调用方可以传数组、`Vec` 或子切片。

### 5. `Copy` 和 `Clone` 有什么区别？

- `Clone` 是显式的 `.clone()`，可以是深拷贝，可能有成本。
- `Copy` 是隐式按位复制，赋值/传参不再移动，原变量仍可用；要求所有字段都是 `Copy`。
- `Copy` 是 `Clone` 的子 trait：实现了 `Copy` 就必须能 `Clone`，但反过来不成立。
- 整数、`bool`、`char`、`&T`、`[T; N]`（`T: Copy`）、元组（各字段 `Copy`）是 `Copy`；`String`/`Vec`/`Box` 不是。

### 6. `match` 与 `if let` 怎么选？为什么 `match` 要求穷尽？

- `match` 必须覆盖所有可能，编译器检查漏掉的分支，新增枚举变体时能立刻发现。
- `if let` 只关心一个模式，等价于带 `_ => {}` 的 `match`，适合「只处理一种情况」。
- 需要多个条件串联时 `if let ... && let ...` 更紧凑；需要返回值时优先 `match`。
- `match` 是表达式，可返回值；分支里用 `@` 绑定、守卫、范围模式做精细判断。

## 二、所有权与生命周期

### 7. 说说所有权的三条规则。

- 每个值有且只有一个所有者。
- 同一时刻只能有一个所有者，赋值/传参/入容器即转移（move）。
- 所有者离开作用域时值被 `drop`，内存自动释放。
- 由此得到：不需要 GC，也不会有 double free 或 use-after-free（安全代码内）。

### 8. Rust 的 move 与 C++ 的 `std::move` 有什么不同？

- C++ 的 `std::move` 只是一个类型转换，产生右值引用，是否真的搬走取决于移动构造；源对象仍处于有效但未指定状态。
- Rust 的 move 是**按位拷贝 + 源变量作废**，编译器此后禁止使用源变量（E0382）。
- Rust 没有移动构造函数，`Drop` 只在最终所有者处执行一次。
- 想让源变量继续可用，就 `clone()` 或改用引用；想显式结束生命周期用 `drop(x)`。

### 9. 借用规则是什么？NLL 改变了什么？

- 任意时刻：要么有任意多个 `&T`，要么有唯一一个 `&mut T`，二者不能同时存在。
- 引用必须始终有效，不能比它指向的数据活得更久。
- NLL（非词法生命周期）把借用的结束点从「块结束」提前到「最后一次使用」，因此很多旧代码不再需要额外作用域。
- 借用检查是编译期的：运行时零开销，代价是某些数据结构（图、双向链表）要用索引、`Rc`/`RefCell` 或 `unsafe`。

### 10. 生命周期标注是在延长变量寿命吗？

- 不是。标注只是**描述**引用之间的有效期关系，告诉编译器「输出借用活不过输入」，不改变任何运行时行为。
- `fn f<'a>(x: &'a str) -> &'a str` 表示返回值与 `x` 同寿，调用方据此检查。
- 生命周期省略规则让常见情形（单输入、`&self`）不必手写。
- 结构体持有引用时也必须带生命周期参数，说明它不能比被借用的数据活得更久。

### 11. `'static` 和 `T: 'static` 是一回事吗？

- `&'static T` 表示引用本身活到程序结束，常见于字符串字面量和 `Box::leak`。
- `T: 'static` 只表示类型内部**不含非静态借用**，`String`、`Vec<i32>`、`i32` 都满足。
- 因此 `T: 'static` 并不要求值永不释放，它只是「没有短命引用」。
- `thread::spawn` 要求 `'static`，因为新线程可能比创建它的栈帧活得更久；需要共享就用 `Arc` 或 scoped thread。

### 12. 什么情况下会得到悬垂引用？编译期怎么拦住？

- 返回局部变量的引用（E0515）、引用临时值（E0716）、引用先于自身被释放的变量（E0597）。
- 编译器用借用检查器追踪每个引用的生命周期区间，发现「引用活过数据」就报错。
- 需要延长数据寿命时：把数据移到堆上（`Box`/`Arc`）、`Box::leak` 得到 `'static`，或用 `Cow` 延迟克隆。
- `unsafe` 里可以绕过检查，但那是 UB，需要自己保证有效性。

## 三、trait 与泛型

### 13. trait 与 Java 接口、C++ 抽象类有什么不同？

- trait 可以为**已有类型**实现（受孤儿规则限制），不需要改原类型定义。
- 支持默认方法、关联类型、关联常量、泛型方法、父 trait 约束。
- 没有继承层次，`impl Trait for Type` 可叠加多个 trait；`dyn Trait` 相当于接口，`impl Trait` 相当于泛型约束。
- 一个类型可以对不同参数实现同一 trait（如 `From<A>`、`From<B>`），关联类型则只允许一种实现。

### 14. 静态分发和动态分发怎么选？

- `impl Trait` / 泛型参数 = 静态分发，单态化后直接调用，可内联、零成本，但会增加代码体积。
- `&dyn Trait` / `Box<dyn Trait>` = 动态分发，经虚表跳转，一次间接调用，运行时才知道具体类型。
- 需要异构集合（`Vec<Box<dyn Trait>>`）、插件式扩展、减小二进制体积时用 `dyn`。
- 热路径、库内部实现、需要内联优化时用泛型；`dyn` 会阻止内联，且要求对象安全。

### 15. 关联类型和泛型参数有什么区别？

- 关联类型（`trait Store { type Item; }`）是「每个实现只能有一种」，用起来不必到处写类型参数。
- 泛型参数（`trait Store<T>`）允许同一类型对多个 `T` 分别实现，表达力更强但调用处更啰嗦。
- `Iterator::Item` 用关联类型，因为一个迭代器只有一种元素；`From<T>` 用泛型参数，因为可以有多个来源。
- 选择标准：概念上「唯一」用关联类型，「多态」用泛型参数。

### 16. 什么是孤儿规则？怎么绕过？

- 只有当 trait 或类型至少有一个定义在当前 crate 时，才能写 `impl Trait for Type`，防止下游出现冲突实现。
- 想在外部类型上实现外部 trait，就用 newtype：`struct Wrapper(ExternalType);` 然后为 `Wrapper` 实现。
- newtype 还能顺带收紧不变量、隐藏内部表示、实现 `Deref` 复用方法。
- 泛型实现要注意覆盖冲突（E0119），必要时用具体类型或标记 trait 拆分。

### 17. trait 对象为什么有「对象安全」限制？

- 虚表只能容纳能在未知具体类型下调用的方法，所以方法不能返回 `Self`、不能有泛型参数、不能有 `where Self: Sized` 之外的自引用约束。
- `fn clone(&self) -> Self` 不满足对象安全，所以 `Clone` 不能直接做 `dyn`；需要 `dyn Clone` 时用专门的 `dyn-clone` 模式或返回 `Box<dyn Trait>` 的辅助方法。
- 关联类型必须指定具体类型（`dyn Iterator<Item = u8>`）才能构成完整类型。
- 类方法（无 `self`）需要 `Self: Sized` 才能与 `dyn` 共存。

### 18. 泛型单态化带来什么代价？

- 每个具体类型组合都会生成一份代码，编译变慢、二进制变大（代码膨胀）。
- 缓解手段：把泛型内核抽成非泛型函数（内部用 `dyn` 或具体类型），外层只做薄封装。
- 常用 `impl Trait` 返回不透明类型也会单态化，注意别在循环里制造大量组合。
- 运行时性能通常更好（可内联、无虚表），这是「零成本抽象」的来源。

## 四、并发

### 19. `Send` 和 `Sync` 分别是什么意思？

- `Send`：所有权可以安全地转移到另一个线程（如 `String`、`Vec`、`Arc<T>`）。
- `Sync`：`&T` 可以安全地共享给多个线程（如 `i32`、`Mutex<T>`、`Arc<T>` 在 `T: Send + Sync` 时）。
- 二者都是自动实现的标记 trait；`Rc`/`RefCell` 既不 `Send` 也不 `Sync`，`Cell` 是 `Send` 但非 `Sync`。
- `T: Sync` 等价于 `&T: Send`；`Mutex<T>: Sync` 要求 `T: Send`。

### 20. `Mutex` 和 `RwLock` 怎么选？

- 读多写少用 `RwLock`（读可并行），写多或临界区短用 `Mutex`（实现更轻）。
- `RwLock` 在部分平台/实现下可能写饥饿，`std` 的实现策略依赖操作系统。
- 两者都会「中毒」（poisoning）：持锁线程 panic 后，后续 `lock()` 返回 `Err`，可 `into_inner()` 取回数据或 `clear_poison()`。
- 临界区越小越好；需要原子计数用 `AtomicUsize`，不要为了一个计数器上锁。

### 21. `Arc<Mutex<T>>` 有什么坑？

- 锁的粒度：抱着锁做 IO 会把整个程序串行化。
- 死锁：同一线程二次 `lock()` 必然卡死（不可重入）；多锁场景要统一加锁顺序。
- 中毒传播：一个线程 panic 会让其他线程拿到 `Err`，要么恢复数据要么放弃。
- 循环引用：`Arc` 互相持有会泄漏，需要用 `Weak` 打断环。

### 22. 消息传递和共享内存怎么选？

- channel 把「共享」变成「转移」，所有权清晰，天然避免数据竞争，适合任务分发与流水线。
- 共享内存（`Arc<Mutex<...>>`）适合需要频繁读写同一份状态的场景。
- `std::sync::mpsc` 是多生产者单消费者，异步场景常用 `tokio::sync::mpsc`（有界队列可做背压）。
- 经验：先用 channel，确实需要共享再上锁；有界队列能防止生产过快的 OOM。

### 23. 线程 panic 之后会发生什么？

- panic 默认展开栈，该线程的局部变量被 drop；其他线程继续运行。
- `JoinHandle::join()` 返回 `Err(Box<dyn Any>)`，可 `downcast_ref` 取回 panic 载荷。
- 若 panic 发生在持锁期间，锁被标记为中毒，后续 `lock()` 返回 `Err(PoisonError)`。
- `panic = "abort"` 时进程直接终止，适合对体积敏感、不吃 RAII 清理的场景。

### 24. `async` 解决了什么问题？为什么还需要 executor？

- 用少量线程处理大量并发 IO：任务在等待时让出线程，而不是阻塞线程。
- `async fn` 编译成状态机（实现 `Future`），只有被 `poll` 才推进；`.await` 是「未就绪就挂起」的语法。
- `Future` 是惰性的，`std` 不提供运行时，必须由 executor（如 tokio）驱动，否则什么都不会发生。
- 代价：`Send` 约束、`Pin`、不能跨 `await` 持非 `Send` 的 guard；CPU 密集任务仍需线程池。

## 五、工程

### 25. workspace 和 features 在真实项目里怎么用？

- workspace 把多个 crate 放在一个 `Cargo.lock` 下，共享 `target/` 与依赖版本，适合「库 + CLI + 集成测试」。
- `[workspace.dependencies]` 集中管理版本，成员用 `x.workspace = true` 继承，避免版本漂移。
- features 做可选依赖与裁剪：`default = ["std"]`，用 `dep:serde` 让可选依赖只在开启时拉入。
- CI 至少跑 `--all-features` 与 `--no-default-features` 两套，防止条件编译分支腐烂。

### 26. 错误处理怎么设计？

- 库对外暴露具体错误枚举（可实现 `std::error::Error`），让调用方能 `match` 处理。
- 应用层用 `Box<dyn Error>` 或统一错误类型，配合 `?` 快速冒泡。
- 用 `From` 实现错误转换，`?` 才能自动 `map_err`；不要到处手写 `.map_err(|e| ...)`。
- 错误信息要带上下文（哪个文件、哪个参数），`thiserror`/`anyhow` 就是为这两层需求服务的。

### 27. 什么时候可以 `unwrap` / `panic`？

- 原型与测试里随便用；生产代码里只用于「逻辑上不可能失败」的情况，并写 `expect` 说明理由。
- 启动期配置错误、违反不变量属于「不可恢复」，`panic` 或 `expect` 可接受。
- 可恢复的错误（IO、解析、网络）必须返回 `Result`，由调用方决定策略。
- 库代码里 `panic` 要写进文档；`unwrap` 在 FFI 边界会引发 UB 风险（跨 `extern "C"` 展开是未定义行为）。

### 28. Rust 的测试有哪几层？

- 单元测试：同文件 `#[cfg(test)] mod tests`，可以测私有函数。
- 集成测试：`tests/` 目录，只能访问 `pub` API，每个文件是独立 crate。
- 文档测试：`///` 里的示例会被 `cargo test` 编译运行，保证文档不腐烂。
- 还有 `#[should_panic]`、`#[ignore]`、基准测试（`benches/`），以及 `cargo test -- --nocapture` 查看输出。

### 29. 编译太慢怎么优化？

- 用 `cargo check` 做日常反馈，`cargo build` 只在实际运行时用。
- 减少泛型爆炸与巨型 crate，把重依赖设为可选或换成更轻的替代。
- `[profile.dev]` 里给依赖开优化（`[profile.dev.package."*"] opt-level = 2`），自己代码保持 `0`。
- 用 `sccache`/`mold`（或平台等价物）做编译缓存与更快链接；`codegen-units` 与 `lto` 只影响 release。

### 30. `unsafe` 用在哪里？review 时看什么？

- 五个超能力：解引用裸指针、调用 `unsafe` 函数、访问 `static mut`、实现 `unsafe trait`、访问 union 字段。
- 常见正当场景：FFI、性能关键的自定义容器、`Pin` 相关的基础设施、SIMD intrinsics。
- review 重点：是否真的需要、安全前提（safety contract）是否写成注释、`Send`/`Sync` 的手动实现是否有依据。
- 尽量把 `unsafe` 封在小模块里，对外只暴露安全 API，并用 `Miri`、`loom`、模糊测试兜底。
